# 《生化危机模拟器》复刻开发报告

> 项目代号：**ZOS-R**（Zombie Outbreak Simulator — Remake）
> 定位：**个人怀旧自用**，不发行、不商业化、不分发
> 报告版本：v1.0（技术方案定稿候选）
> 目标：在**保留 2009 年原版核心玩法**的前提下，用现代技术重做表现层

---

## 0. 摘要（一页纸结论）

| 项 | 结论 |
|---|---|
| 技术路线 | **浏览器 Web 优先**：Vite + TypeScript + Three.js + MapLibre GL JS |
| 核心架构 | **模拟内核（SimCore）与渲染层彻底分离**，20Hz 确定性 tick + 60fps 插值渲染 |
| 模拟实现 | 纯 TypeScript + TypedArray（SoA），跑在 Web Worker；**不引入 ECS 引擎、不引入物理引擎** |
| 世界数据 | **OpenStreetMap**（建筑轮廓/道路/POI）→ 本地烘焙成瓦片 → Three.js 自建几何；MapLibre 只当"地面贴图" |
| 角色渲染 | **VAT（顶点动画贴图）+ InstancedMesh**，12,000–15,000 个角色单帧 < 8ms |
| 底图方案 | MapLibre 画地面影像，**相机由 Three 反向驱动 MapLibre**（不用 custom layer、不做矩阵 hack） |
| 确定性 | 种子 PRNG + 固定步长 + 有序遍历 + 三角函数查表 → **同参数复现同一局**，可回放、可分享、可回归测试 |
| 最大的三个风险 | ① 坐标精度/浮点抖动 ② MapLibre 与 Three 的相机同步漂移 ③ 万级角色动画的显存与带宽 |
| 单人总工期估计 | **6–8 周**（每周 20–25 小时）到"能玩、好玩、好看"的自用版本 |
| 关键"钩子"功能 | **2009 复古模式**：同一份 sim，换一套渲染器，一键切回当年的红绿点 |

## 1. 项目定位与非目标

### 1.1 要保留的四条核心玩法（不可动）

1. **零操控** —— 玩家永远不能直接指挥任何一个平民或丧尸，只能调参数与"干预"。
2. **真实地点** —— 地图是真实世界的一处（卫星影像 + 真实建筑轮廓）。
3. **参数即玩法** —— 平民数/武装率/枪法/尸速/感染时间/爆发方向/警力数量与精度。
4. **三种结局** —— 丧尸被清剿 / 城市沦陷 / 人尸对峙。

### 1.2 明确不做（防止范围膨胀）

- ❌ 不做角色扮演视角（不操作小人）
- ❌ 不做多人联机（存档/种子分享足够）
- ❌ 不做编辑器（原版 C3O 的地图编辑器是另一个项目）
- ❌ 不做移动端适配（自用，PC 1080p 起步）
- ❌ 不做商业化相关（内购、广告、账号、埋点）
- ❌ 不追求"全球任意城市一键可用"（先做 1–2 个英雄城市，够玩就行）

### 1.3 现代版要补的东西（这是"复刻"的意义）

原版缺的不是技术，是**反馈**：它只给你一堆会动的点。现代版的价值在于让"点"变成"人"，让"数字"变成"事件"。

| 现代增强 | 成本 | 情绪价值 |
|---|---|---|
| 单点追踪（点小人 → 名字/职业/家庭/感染倒计时） | 低 | ★★★★★ |
| 镜头导演（自动切到"有戏"的瞬间 + 慢放） | 中 | ★★★★★ |
| 昼夜 + 天气 + 体积光 | 中 | ★★★★ |
| 热成像/夜视视角（感染者体温高，一眼看穿谁被咬） | 低 | ★★★★ |
| 感染曲线/伤亡名单/新闻标题生成 | 低 | ★★★★ |
| 时间轴回放 + 种子分享 | 中 | ★★★★ |
| 2009 复古模式（红绿点 + 原版 UI） | 低 | ★★★★★ |
| 行动后报告（评分/时间线大事记） | 低 | ★★★ |

## 2. 技术选型（含备选对比）

### 2.1 引擎/框架

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **Three.js + TypeScript** | 迭代最快、Web 生态最成熟、与地图库天然共存、包体小 | 没有编辑器，光照/工具链要自己搭 | ✅ **选它** |
| Babylon.js | 内置物理/PBR/编辑器、TS 原生 | 包体大、社区偏企业向 | 备选 |
| Bevy (Rust) | ECS 天生适合万级 agent、可同时出原生版 | 生态年轻、UI 弱、编译期长 | 若将来要 10 万 agent 再考虑 |
| Godot 4 | 引擎完整、导出桌面方便 | 万级动画实例化要自己写内核 | 不选（Web 表现力弱） |
| Unity | 工具链最完整 | 重、启动慢、Web 导出现在很差 | 不选 |
| Unreal | 画面上限最高 | 万级 agent + 编译时间 + 学习成本 | 不选 |

**理由**：自用项目最重要的是"今天晚上就能改一行看到效果"。Three.js 的热重载反馈循环是 1 秒级，Unity 是分钟级。

### 2.3 为什么不把模拟放进 React

## 3. 系统架构

### 3.1 模块图

```
┌──────────────────────────────────────────────────────────────┐
│  UI 层（React）                                               │
│  参数面板 / 统计曲线 / 单点卡片 / 时间轴 / 视角切换            │
└───────────────┬──────────────────────────────▲───────────────┘
                │ 指令（参数、干预、变速）       │ 汇总数据 10Hz
┌───────────────▼──────────────────────────────┴───────────────┐
│  Worker：SimCore（纯 TS，零依赖，可在 Node 里跑）              │
│  world / grid / flow / agents / step / events / rng           │
│  20Hz 固定步长 · 确定性 · 输出 SoA 快照                        │
└───────────────┬──────────────────────────────────────────────┘
                │ Transferable ArrayBuffer（双缓冲）
┌───────────────▼──────────────────────────────────────────────┐
│  渲染层（Three.js）                                           │
│  CameraRig / Basemap(MapLibre) / City / Agents(VAT) /         │
│  Shadow / Decals / Particles / Post / Audio                   │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 线程模型

- **主线程**：渲染 + UI + 输入。
- **Worker 线程**：模拟（20Hz）。即使主线程掉帧、切标签页、断点调试，模拟也照常推进。
- **通信**：优先用 `postMessage` + **Transferable ArrayBuffer 双缓冲**（每帧约 0.5MB，20Hz ≈ 10MB/s，完全无压力）。
  - 备选 `SharedArrayBuffer`：需要 COOP/COEP 响应头（Vite 里配 `server.headers` 即可）。**先用 Transferable**，因为零配置、零心智负担；只有当 profiler 显示 postMessage 占用 >1ms 时才切换。
- **插值**：渲染层同时持有 `snapshot[n-1]` 与 `snapshot[n]`，按 `alpha = (now - tickTime)/dt` 线性插值位置与朝向 → 20Hz 模拟也能出 60fps 顺滑画面。

### 3.3 快照数据布局（SoA）

```ts
// 每个 tick 输出一份，双缓冲交替
interface Snapshot {
  tick: number;
  count: number;              // 存活 agent 数
  posX: Float32Array;         // 米（相对 tile 原点）
  posY: Float32Array;
  dir:  Uint8Array;           // 朝向，量化到 256 份，省带宽
  state: Uint8Array;          // 0 平民 1 恐慌 2 持枪 3 警 4 兵 5 丧尸 6 尸体
  clip: Uint8Array;           // 动画片段索引
  phase: Uint8Array;          // 动画相位（0-255）
  tint: Uint8Array;           // 调色板索引（4 种体型 × 8 种配色）
  flags: Uint8Array;          // bit0 被感染(潜伏) bit1 开火 bit2 倒地
  stats: SimStats;            // 人口/感染/警力/伤亡曲线点
}
```

> **带宽核算**：12,000 × (4+4+1+1+1+1+1+1) = **168KB / 快照**，20Hz → 3.4MB/s。可接受。

## 4. 世界数据层（从 OSM 到可玩的城市）

### 4.1 数据源与法务口径

| 数据 | 来源 | 个人自用可行性 |
|---|---|---|
| 建筑轮廓 / 高度 / 道路 / POI / 树 | **OpenStreetMap**（ODbL） | ✅ 完全没问题，署名即可 |
| 卫星影像（地面贴图） | MapLibre 接 MapTiler / Mapbox / Esri 免费额度 | ✅ 免费额度对个人玩完全够（100k 瓦片/月级别） |
| Google 卫星图 | Google Maps Platform | ⚠️ 条款对缓存/衍生/嵌入限制极严，且不区分商用与非商用。**建议不碰**，用上面的方案替代，观感差异很小 |
| 3D 建筑（现成） | Cesium OSM Buildings（3D Tiles） | ✅ 可参考，但我们要自己烘焙才好控制材质 |

> **重要提醒**：不要写脚本批量抓整座城市的瓦片。各家的 Tile Usage Policy 都对"批量下载"有限制。个人自用缓存一个 1–2km² 街区没问题，别做成爬虫。

### 4.2 坐标系与浮点精度（第一个大坑）

**问题**：Web Mercator 的世界坐标单位是"米"，但原点是赤道/本初子午线，一座城市的坐标动辄是 `x = 13,000,000`、`y = 4,800,000`。把它塞进 `Float32`（7 位有效数字）→ **精度只剩 1–10 米**，模型会抖、会闪、会错位。

**方案**：

1. **本地原点（Local Origin）**：每个 tile 用自己 bbox 中心做原点，所有几何/模拟坐标都是 ±500m 的小数字。**模拟层用 Float64**，**渲染层用 Float32 相对坐标**。
2. **浮动原点（Floating Origin）**：相机移动超过 2km 时，整体重定基（把所有几何的 position 平移）。自用场景一次只玩 1–2km²，这条可以暂不实现，但架构上留好接口。
3. Mercator 在纬度 φ 处有尺度畸变 `1/cos(φ)`：换算"米"时必须乘 `cos(φ)`，否则你的城市在南北方向会被拉长。**这是必须写进管线的常数**。

```python
# 维度正确的局部投影（米）
R = 6378137.0
def lnglat_to_local(lng, lat, lng0, lat0):
    k = math.cos(math.radians(lat0))          # 尺度因子
    x = math.radians(lng - lng0) * R * k
    y = math.radians(lat - lat0) * R
    return x, y
```

### 4.3 管线流程（Python，一次性预处理）

```
Overpass API / Geofabrik .osm.pbf
        │  按 bbox 拉取：way[building], building:levels|height,
        │  highway=*, natural=tree, landuse=*, amenity=*（POI）
        ▼
  清洗 & 简化（shapely + Douglas-Peucker，容差 0.8m）
        │  丢弃 < 12m² 的附属物、合并贴合的重叠轮廓
        ▼
  高度推断（优先级）
        │  1. building:height
        │  2. building:levels × 3.2 + 1.5
        │  3. 面积启发式：<80m² → 6m；80–400m² → 9m；
        │     400–2000m² → 15m；>2000m² → 24m
        │  4. 中心城区系数 ×1.6（用 POI 密度判定中心）
        ▼
  几何生成（numpy + trimesh / earcut）
        │  轮廓三角化 → 挤出 → 屋顶内缩 0.3m 做女儿墙
        │  每条竖直边生成 UV（用于程序化立面）
        ▼
  导航栅格栅格化（2m 分辨率）
        │  Uint8: 0 建筑(不可走) 1 道路/人行道 2 绿地(减速)
        │  对建筑轮廓做 0.3m 膨胀（防止贴墙卡住）
        ▼
  装饰散布（Poisson-disk）
        │  行道树（沿道路每 8–14m）、路灯、路边停车、
        │  屋顶空调/水塔/招牌
        ▼
  导出自定义二进制 .zosworld
        │  header + 建筑数组 + 栅格 + 装饰实例 + POI 表
        ▼
  Three.js 加载 → 构建 BufferGeometry（合并静态几何，1 draw call / tile）
```

**为什么不用现成 addon**：`blender-osm` 之类的插件产出的几何面数高、材质不可控、且无法同时产出导航栅格。自建管线虽然多写 300 行 Python，但后续所有"玩法数据"（POI、可走性、楼层数）都能一次拿全。

**Blender 什么时候用**：只用来做**道具模型**（救护车、直升机、士兵、路障、军卡），一次性导出 GLB 即可。楼体不用 Blender 做——程序化立面 shader 能省掉全部贴图和 UV 劳动。

### 4.4 建筑的程序化立面（零贴图方案）

把整片街区的楼合并成一个 mesh，每条竖直面在生成时写入两个自定义属性：`aFloorH`（层高）与 `aSeed`（随机种子）。片元着色器里根据世界坐标算窗格：

```glsl
// 竖直面：u = 沿墙水平方向的米数，v = 世界高度
float floorId = floor(vWorldY / aFloorH);
float uu      = fract(vWallU / 2.6);                 // 2.6m 一个窗位
float vv      = fract(vWorldY / aFloorH);
float isWin   = step(0.18, uu) * step(uu, 0.82)
              * step(0.25, vv) * step(vv, 0.78);
vec3 wall     = mix(aWallTop, aWallBottom, vWorldY / aHeight);
vec3 glass    = aGlassBase * (0.6 + 0.4 * noise(vWallU, vWorldY));
vec3 col      = mix(wall, glass, isWin);
// 夜间：随机亮灯（同一个 hash 保证稳定，不会闪）
float lit = step(0.62, hash21(vec2(floorId, floor(vWallU / 2.6)) + aSeed));
emissive += isWin * lit * uNightAmount * vec3(1.0, 0.86, 0.62);
// 立面污渍、雨痕、首层商铺（v < 4m 换成招牌色）
```

好处：**零贴图、零 UV 劳动、无限变化、夜间自然亮灯、显存开销几乎为零**。这是"现代画面"最划算的一笔投资。

### 4.5 地面（MapLibre 的正确用法）

```ts
// 底图 = 一张跟随相机的平面影像
const map = new maplibregl.Map({
  container: basemapEl,          // z-index: -1 的 div，铺满屏幕
  style: 'maptiler://satellite', // 只保留影像层，关掉所有 label
  interactive: false,            // 输入全部交给 Three
});
map.setLayoutProperty('roads', 'visibility', 'none'); // 城市自己画道路，别打架
```

**关键点**：MapLibre 的 label 会被画在 3D 建筑**底下**（因为它在 Three 的 canvas 下面），看起来像"字飘在楼里"。所以底图样式里**必须关掉所有文字**，路名/地名的标签由 Three 里的 Sprite 自己画（还能被楼正确遮挡）。

## 5. 相机与底图同步（第二个大坑）

### 5.1 方案对比

| 方案 | 原理 | 优点 | 缺点 |
|---|---|---|---|
| A. Three 挂进 MapLibre custom layer | MapLibre 提供 `render(gl, matrix)` | 建筑与角色共享深度，遮挡天然正确 | MapLibre 的 GL 状态与深度范围（near/far 极大）会让 2 米高的人 z-fighting；坑极多 |
| B. 两张 canvas + 各自相机 | 上层透明 Three 画人，下层地图 | 隔离干净 | 人永远画在楼上面（穿墙），假的 |
| **C. 反向同步（推荐）** | **Three 是主世界，MapLibre 只当底图** | 深度/阴影/光照全归自己；无矩阵 hack；相机数学确定 | 底图晚一帧（无感）；楼是"自己画的"不是地图给的 |

**选 C**。理由：我们要的"现代画面"（实时阴影、体积光、PBR、后处理）在方案 A/B 里全部受制于地图库；方案 C 里 MapLibre 退化成一张会跟着动的地面贴图，代价几乎为零。

### 5.2 同步数学

```ts
// 每帧：Three 相机状态 → MapLibre 的 jumpTo
const { lng, lat } = tile.localToLngLat(rig.focus.x, rig.focus.y);
map.jumpTo({
  center: [lng, lat],
  zoom:  rig.zoom,        // 由相机高度反算
  pitch: rig.pitch,       // 0–60°
  bearing: rig.bearing,
});
```

反算关系（正射近似）：

```ts
// zoom ← 相机到地面高度 h（单位：米），纬度 φ
// 世界像素 = 256 * 2^zoom 覆盖 2πR*cos(φ) 米
function heightToZoom(h: number, latDeg: number, fovDeg: number, viewportH: number) {
  const mPerPx = (2 * Math.PI * 6378137 * Math.cos(latDeg * Math.PI / 180) * Math.sin(fovDeg * Math.PI / 360))
               / viewportH;                       // 相机在 h 高度时，地面每像素的米数
  const worldMeters = 2 * Math.PI * 6378137 * Math.cos(latDeg * Math.PI / 180);
  return Math.log2(worldMeters / (256 * mPerPx));
}
```

**验收标准**：在画面里放一个已知地标（如华盛顿纪念碑的坐标），用 Three 的 `project()` 和 MapLibre 的 `map.project()` 各算一次屏幕坐标，误差必须 **< 2px**。这条写成自动化测试，否则你会花一整天怀疑"是不是我的楼盖歪了"。

### 5.3 相机手感（这是"好不好玩"的一半）

- **默认**：RTS 式上帝视角，俯角 55°，视野 45mm 等效。
- **平移**：WASD / 中键拖拽，边缘吸附。
- **缩放**：滚轮以鼠标位置为锚点（`zoom to cursor`），不是以屏幕中心。
- **俯仰**：右键拖拽 0–75°，压到贴近地面时有轻微鱼眼（可选）。
- **跟随**：双击任意 agent → 相机平滑追踪（带阻尼 + 提前量）。
- **导演模式**：自动挑选"有戏"的目标切镜（见 §9.4）。
- **加速**：按住 Shift 时相机移动 ×4。

## 6. 导航与流场（第三个大坑，但是最有趣的一个）

### 6.1 为什么不用 A*

12,000 个 agent 每个 20Hz 做 A*，等于每秒 24 万次寻路 —— 不现实，且行为会"整齐划一"（所有人沿同一条最优路径排成一列）。

### 6.2 多源流场（Multi-source Flow Field）

```ts
// 每个 tile 的导航数据
walkable: Uint8Array(W * H)    // 0 不可走 / 1 道路 / 2 绿地(代价×1.6) / 3 门口
dist:     Uint16Array(W * H)   // 到最近"威胁源"的代价（单位：0.1m）
flow:     Int8Array(W * H)     // 0..7 方向索引，-1 无方向
```

- **威胁源**：最近的一批平民/警察（用空间哈希粗选，最多 8 个源）。
- **求解**：桶队列 Dijkstra（8 邻域，对角权重 √2），2m 栅格 / 1km² = 250k 格，一次约 **3–6ms**。
- **更新策略**：每 10 tick（0.5s）重算一次，**按 tile 分帧错开**，避免同一 tick 卡顿。
- **流动感**：agent 沿 flow 走 + 邻域分离力（避免叠在一起）→ 自然形成"堵在路口""挤过窄巷""在广场上摊开"的尸潮形态。这是 2009 年做不到的**涌现感**，也是复刻版最值得炫耀的东西。

### 6.3 平民的导航

平民不需要流场。他们用**目标点 + 直线避障**：

1. 从 POI 表里选一个"安全点"（家 / 商店 / 地铁口 / 警局），加入 `targetId`。
2. 朝目标直线走，遇到建筑栅格用**局部切向绕行**（沿着墙滑，steering 里的 `wall-follow`）。
3. 走不到就换目标（最多重试 3 次），再造一个"慌不择路"的效果 —— 这个失败行为**本身就是玩法**。

### 6.4 碰撞与拥挤

- 不与建筑做逐面碰撞，而是查栅格：进入 `walkable==0` 的格子就沿法线推出去（O(1)）。
- agent 之间的分离：查空间哈希 3×3 邻格，只对最近 8 个做排斥力，避免 O(n²)。
- 拥挤度会真实影响速度（`speed *= 1/(1+0.15*neighbors)`），于是**人群会自己堵成瓶颈**，警察的子弹会打在自己人身上（可选开关）。

## 7. 模拟内核（SimCore）

### 7.1 每 tick 的执行顺序（顺序即确定性）

```
step(tick):
  1. applyEvents(tick)      // 干预指令按 tick 排队，绝不按"到达时间"执行
  2. rebuildSpatialHash()   // 计数排序，O(n)，每 tick 重建
  3. sense()                // 只读上一 tick 的状态 → 无顺序依赖
  4. decide()               // 状态机 + 效用值
  5. steer()                // 转向力合成（流场/避障/分离/目标）
  6. integrate(dt)          // 位置积分（Float64）
  7. resolveCollisions()    // 栅格推出 + 邻居分离
  8. infectAndKill()        // 接触判定 → 潜伏计时 → 转化 / 死亡
  9. collectStats()         // 曲线采样
 10. emitSnapshot()         // 双缓冲
```

**铁律**：`sense` 阶段只能读上一 tick 的状态数组，不能读本 tick 已经被修改的数组。否则结果依赖遍历顺序，确定性就没了。

### 7.2 状态机

```
平民 Civilian
 ├─ IDLE ──感知威胁──► FLEE
 ├─ FLEE ──到达安全点──► HIDE（静止、瑟瑟发抖、可被找到）
 ├─ FLEE ──持枪且威胁近──► FIGHT（站定射击，命中率由参数决定）
 └─ 任意 ──被咬──► INFECTED（潜伏 T 秒，速度下降 40%，可传染）
感染 INFECTED ──计时到──► ZOMBIE
警察 Police ──► ENGAGE（优先射击最近丧尸，精度更高、弹药有限）
士兵 Soldier ──► 伞降落地 → 建立防线 → 弹药耗尽转近战
丧尸 Zombie ──► SEEK（流场）→ ATTACK（接触）→ FEED（原地啃食 3–8s，可被打断）
尸体 Corpse ──► 30s 后淡出（或永久保留，看性能）
```

### 7.3 感知模型（决定"看起来聪明不聪明"）

| 感官 | 规则 | 备注 |
|---|---|---|
| 视觉 | 距离 25m + 前方 120° 锥形；被建筑遮挡则失效（栅格射线，DDA 步进，最多 25 步） | 夜间/雨雾距离 ×0.5 |
| 听觉 | **事件驱动**：枪声半径 80m、尖叫 20m、爆炸 200m；只处理事件，不逐人算 | 丧尸会被枪声吸引 → "开枪=招怪"，天然的策略张力 |
| 恐慌传播 | 半径 15m 内的平民互相抬升 panic 值，panic > 阈值才逃 | 于是"人群炸开"是逐步扩散的，不是瞬间全体逃跑 |
| 血液/气味 | 尸体半径 10m 吸引丧尸 | 让"战场边缘堆积"自然地出现 |

### 7.4 确定性清单（照做，不然回放会飘）

```ts
// ✅ 允许
Math.floor / Math.abs / Math.sqrt / 四则运算 / 位运算
// ❌ 禁止
Math.random()        → 用 mulberry32(seed + tick * 7919 + agentId)
Math.sin/cos/tan     → 用 2048 项查表（不同浏览器 JS 引擎的实现可能末位不同）
Date.now()/performance.now() → 模拟里绝对不能出现
new Set()/new Map() 遍历顺序 → 只用数组，按下标遍历
Array.prototype.sort 无 tiebreak → 必须显式 `(a,b)=> (a.v-b.v) || (a.id-b.id)`
```

**自证方法**：跑 `seed=42, 60 秒`，对每 5 秒的状态数组做 FNV-1a 哈希，把 12 个哈希值钉进单元测试。任何一次重构导致哈希变化，立刻就知道"我改坏了确定性"。

## 8. 渲染层

### 8.1 场景图结构

```
Scene
├─ GroundPlane        (ShadowMaterial，只接收阴影，透明)
├─ City               (静态合并几何：楼/路/树/路灯/车，按 tile 分块，LOD)
├─ Agents             (InstancedMesh × 4 体型，VAT 动画)
├─ BlobShadows        (InstancedMesh，圆片假阴影，1 draw call)
├─ Particles          (GPU instanced billboards：血、烟、火星、弹壳)
├─ Decals             (血渍累积贴图，见 8.5)
├─ Effects            (探照灯体积光锥、空袭标记、烟雾体积)
├─ Labels             (路名/地名的 Sprite，自己画才能被楼遮挡)
└─ Post               (Bloom → 色调映射 → 颗粒 → 暗角 → 色差)
```

### 8.2 建筑渲染

- 一个 1km² 街区一次性合并成 1–3 个 mesh（按材质变体分批）：约 2,000 栋楼 / 40–80 万三角形 / **1–3 个 draw call**。
- 材质：`MeshStandardMaterial` 的 `onBeforeCompile` 注入程序化立面（见 §4.4）。PBR 参数：混凝土 roughness 0.85、玻璃 0.15 + metalness 0.4。
- 楼高数据缺失时用启发式（§4.3），并在 UI 里标一个"估算"图标 —— **诚实**比假装准确好。

### 8.3 角色渲染（本项目最大的性能工程）

**核心方案：VAT 顶点动画**

1. 在 Blender 里做一个 1.75m 高的低模人形（约 300 面），绑 8 根骨骼。
2. 烘焙 5 套动作：`walk` / `run` / `fight` / `feed` / `fall`，每套 32 帧，30fps。
3. 逐帧把顶点位置写进纹理（RGBA16F）：宽 = 顶点索引（≤1024），高 = 动作×帧数（5×32=160）。
4. 顶点着色器里按 `instanceId → phase → clip` 采样两次（当前帧/下一帧）做线性混合。

```glsl
// 顶点着色器核心
float t = (aPhase / 255.0) * 32.0;            // 相位 → 帧
vec2 uvA = vec2(aUV.x, (clipBase + floor(t)) / 160.0);
vec2 uvB = vec2(aUV.x, (clipBase + ceil(t)) / 160.0);
vec3 pA = texture2D(vatPos, uvA).xyz;
vec3 pB = texture2D(vatPos, uvB).xyz;
vec3 p  = mix(pA, pB, fract(t)) * uScale + uOffset;
```

- **显存**：1024×160 RGBA16F ≈ 1.3MB；法线贴图 RGBA8 ≈ 0.65MB。**合计 2MB 驱动 12,000 个角色**。
- **为何不用骨骼蒙皮**：骨骼矩阵要逐人 CPU 计算并上传（12,000 × 8 骨 × 64B ≈ 6MB/帧），带宽直接爆。VAT 是纯采样，GPU 侧零开销。
- **为何不用动画贴图 + 顶点压缩的第三方库**：自己写 40 行 shader 就够了，依赖越少越好。

**体型/配色多样性**：
- 4 种体型（男/女/壮/瘦），每种一个 InstancedMesh。
- 每实例一个 `aTint`（0–7），在片元着色器里映射到 8 套配色（衣服/裤子/肤色）。
- 组合数 = 4×8 = 32 种外观，肉眼基本看不出重复。

**LOD（必须做，否则 12,000 个角色同时全精度会死）**：

| 距离 | 方案 | 三角形 | 数量级 |
|---|---|---|---|
| 0–40m | 完整 VAT 角色 | 300 | 通常 < 300 个 |
| 40–150m | 简化 VAT 角色（80 面），动画 15fps | 80 | 1,000–3,000 |
| >150m | **发光点云 billboard**（1 个 quad） | 2 | 剩下全部 |

> 远处退回点云不是妥协，是**致敬**：这正是 2009 年原版的形态。而且在上帝视角下，点云的"可读性"远高于一堆蚂蚁大小的人形。屏幕上永远只有 2 种视觉状态：清晰的人，和流动的光点。

### 8.4 阴影

| 对象 | 方案 | 理由 |
|---|---|---|
| 建筑/树/车（静态） | 1 张 2048² 平行光 shadow map，**只在太阳/相机大幅移动时重烘** | 静态物体可以烘一次用很久（甚至烘进贴图） |
| 角色（动态） | **假阴影**：InstancedMesh 圆片 + 径向渐变 alpha，按太阳角度拉长 | 12,000 个真实阴影投射者 = 帧率杀手；圆片视觉上够用 95% |
| 夜间 | 路灯/车灯/枪口火光作为点光源（最多 8 个）+ 发光体积锥 | 点光源超过 8 个就改用 emissive + 屏幕空间泛光伪造 |

### 8.5 血渍与痕迹（便宜但极出效果）

- 一张 2048×2048 的 `WebGLRenderTarget` 覆盖整片 1km² 地面，初始全黑。
- 每次"咬死/中弹/爆炸"，往上面 stamp 一个血斑 quad（加法混合，不计深度）。
- 地面渲染时用这张图作为 `decalMap`（乘到地面颜色上）。
- 效果：**战场会在地面上留下历史**，一局玩下来地图是"脏"的。这个细节的情绪价值极高，成本不到 100 行。

### 8.6 后处理与色彩

| 效果 | 参数建议 | 备注 |
|---|---|---|
| Bloom | 阈值 0.85，强度 0.3 | 让夜间窗光、警灯、枪火发光 |
| 色调映射 | ACES Filmic，曝光 0.9 | 现代感的基础 |
| 胶片颗粒 | 强度 0.02 | 掩盖低模的"塑料感" |
| 暗角 | 0.25 | 聚焦视线 |
| 色差 | 0.002 | 只在受伤/爆炸时临时拉高 |
| 景深 | 只在"导演模式/街景"开启 | 上帝视角开景深会看不清战场 |

> **透明画布 + 后处理的坑**：Three 的 canvas 是 `alpha: true` 叠在 MapLibre 上面的，`EffectComposer` 默认会把 alpha 覆盖掉（底图消失）。解法：composer 用 `WebGLRenderTarget({ format: RGBAFormat, type: HalfFloatType })`，最后一个 pass 保留 alpha；或者干脆接受"后处理时把底图也画进去"——把 MapLibre 的 canvas 作为 texture 采样进第一个 pass（更好看，能一起做 bloom，但多一次全屏拷贝）。**推荐后者**，一次解决所有 alpha 与色彩一致性问题。

### 8.7 三种视角模式

| 模式 | 实现 | 用途 |
|---|---|---|
| 卫星/白天 | 默认 | 主要游玩 |
| 夜视 | 全屏后处理：绿色 tint + 噪点 + 边缘增强 | 夜间潜行感 |
| **热成像** | 用自定义材质把 agent 渲成"温度"：活人白热、感染者橙红高亮、尸体冷蓝；建筑半透明 | **既是视觉奇观也是战术工具** —— 被咬还在潜伏的人会显形 |

热成像的实现要点：不要真的做热辐射，直接一张 `temperature` 缓冲（agent 状态 → 颜色），加 `blur` 再叠加。半小时能写完，效果炸裂。

## 9. 音频（一半的沉浸感在这里）

### 9.1 架构

```
Sim（事件流）──► AudioBridge ──► WebAudio
  枪声/尖叫/爆炸/直升机/警笛         │
                                    ├─ 近场：PannerNode 池（最多 24 个，按距离+重要性分配）
                                    ├─ 中远场：预混的"人群底噪"循环，音量/滤波随密度变化
                                    └─ 全局：环境层（风声/雨声/远处城市嗡嗡声）
```

**为什么限制 24 个 Panner**：WebAudio 的 `PannerNode` 每个都要做 HRTF 卷积，几百个会直接爆 CPU。做法是**事件分级**：只有最近的、最响的、最"重要"（剧情性）的 24 个事件获得真实 3D 声源，其余合并成底噪。

### 9.2 声音列表（先用免费素材，不要自己录）

| 事件 | 素材 | 处理 |
|---|---|---|
| 手枪/步枪连射 | 3–4 个变体，随机 pitch ±5% | 距离 >60m 加低通 + 混响，模拟远处 |
| 尖叫（男/女/儿童） | 6 个变体 | 会被 panic 值调制音高 |
| 丧尸低吼 | 8 个变体循环 | 用"僵尸合唱"：同屏多只时相位错开 |
| 咬合/撕裂 | 3 个 | 近距离才播，配合屏幕血渍 stamp |
| 直升机旋翼 | 1 个循环 | 多普勒效应（靠近时 pitch 升） |
| 空袭投弹/爆炸 | 2 个 | 前 1.2 秒是"哨音"，再爆炸 → 情绪张力 |
| 环境底噪 | 城市/雨/风 | 与天气系统联动 |

### 9.3 音频驱动玩法

**枪声会吸引丧尸**（§7.3）——声音系统不只是装饰，它是模拟的输入源。玩家会自己发现"开枪 = 招怪"，这是原版没有的策略深度。

### 9.4 镜头导演（Director）

每 2 秒扫一遍候选事件，打分：

```ts
score = 0.35 * 威胁度（附近丧尸数）
      + 0.25 * 稀缺性（警察/士兵被围）
      + 0.20 * 情绪（平民 vs 丧尸的近距离接触）
      + 0.10 * 视觉（是否在画面内、是否被遮挡）
      + 0.10 * 随机抖动（避免死板）
```

分数最高的目标 → 相机平滑飞过去 + 轻微慢放（0.4x）+ 加黑边 + 音效聚焦。停留 6–10s 后回到玩家相机。**这是"看起来像电影"和"看起来像沙盘"的分水岭**。

## 11. 存档 / 回放 / 分享

### 11.1 回放格式（确定性带来的一条捷径）

```ts
interface Replay {
  version: 1;
  seed: number;            // 一局的根本
  world: string;           // tile 的 hash（保证用的是同一份地图）
  params: OutbreakParams;  // 参数
  events: { tick: number; type: 'airstrike'|'soldiers'|'heli'|'vaccine'; x: number; y: number }[];
  snapshots?: Uint8Array[];// 每 600 tick 一份快照（可选，用于"随便拖时间轴"）
}
```

- **完整回放 ≈ 2KB**（种子 + 参数 + 几十个干预事件）。
- `JSON` 存 IndexedDB，或压成 base64 塞进 URL —— **分享一个链接 = 分享一整局**。
- 想"任意拖动时间轴"就每 30 秒存一份快照（12,000 agent × 168KB ≈ 2MB/份，一分钟 4MB，一局 20 分钟 80MB —— 存 IndexedDB 没问题，注意配额）。

### 11.2 行动后报告

一局结束（或玩家手动结算）生成：

- **结局判定**：清剿 / 沦陷 / 对峙
- **时间线**：第一次感染、第一个死亡、警察全灭、空袭、被救出人数
- **曲线图**：人口 / 感染 / 丧尸数随时间
- **一句话新闻标题**（模板生成）："华盛顿特区东北部爆发不明疫情，军方已介入，死亡人数升至 3,412 人"
- **评分**：存活率 × 时间 × 平民伤亡惩罚

## 12. 性能预算与优化清单

### 12.1 目标（1080p / 中端独显 / 60fps）

| 项 | 预算 |
|---|---|
| 帧时间 | ≤ 16.6ms（留 2ms 余量 → 实际目标 14ms） |
| Draw calls | < 300 |
| 三角形 | < 8M |
| 显存 | < 1.2GB |
| 内存 | < 2GB |
| 模拟 tick | ≤ 8ms（20Hz 下占 16% 单核） |
| Worker → 主线程 | ≤ 1ms/帧 |

### 12.2 分解

| 阶段 | 估计 |
|---|---|
| 模拟（12k agent，含流场分帧） | 5–8ms / tick |
| 建筑渲染（合并几何） | 2–3ms |
| 角色渲染（VAT + 实例化 + LOD） | 3–5ms |
| 假阴影 + 粒子 + 血渍 | 1–2ms |
| 后处理 | 2–3ms |
| MapLibre 底图 | 1–2ms（可降到 30fps 刷新） |
| **合计** | **14–23ms** ← 需要优化 |

### 12.3 优化顺序（按性价比）

1. **MapLibre 降到 30fps 刷新**（`map.repaint` 节流）→ 省 1ms，画面上完全看不出。
2. **角色 LOD 的分界距离收紧**（150m → 120m）→ 省 2–3ms。
3. **粒子池上限 8,000**（不是 20,000）。
4. **血渍贴图降到 1024²**。
5. **后处理合并成一个 shader**（Bloom + 颗粒 + 暗角 + 色差一趟做完），省两次全屏拷贝。
6. 建筑按 tile 做**视锥剔除 + 距离剔除**（>800m 的 tile 不画）。
7. 极端情况：把模拟降到 15Hz（人眼几乎看不出），渲染保持不变。

## 13. 测试与调试工具

自用项目最容易死的地方是"改着改着不知道哪里坏了"。这四样工具必须一开始就写，总成本一天：

1. **无渲染批量跑**（Node 里 import SimCore）：
   ```bash
   npm run batch -- --seeds 1-100 --params defaults.json --out csv
   ```
   输出 100 局的结局分布 → 用来调参数（比如"默认参数下 70% 局会沦陷"是否合理）。
2. **确定性回归测试**（vitest）：固定 seed 的哈希快照，改代码后一跑就知道坏没坏。
3. **调试可视化层**（按键切换）：导航栅格 / 流场箭头 / 空间哈希格子 / 感知锥 / 目标连线。
4. **性能 HUD**：帧时间分解（sim / city / agents / post），不是只有一个总帧率。

## 15. 里程碑与验收标准

> 每个里程碑必须**可测**。达不到就停下修，别往下叠。

### M0 · 技术验证（1–2 天）

**交付**：一个能跑的空场景 —— MapLibre 卫星底图 + 12,000 个立方体在街道上沿流场移动 + 帧率显示。

**验收**：
- [ ] 1080p 下 ≥ 55fps
- [ ] 相机平移/旋转/缩放跟手，无明显延迟
- [ ] 底图与 Three 场景对齐误差 < 2px（地标测试）

### M1 · 模拟内核（3–5 天）

**交付**：SimCore 跑通，Worker 里 20Hz tick，参数面板可调，三种结局判定，变速 0/1/4/16。

**验收**：
- [ ] 12,000 agent 单 tick ≤ 8ms
- [ ] 同 seed 跑两次，每 5 秒状态哈希完全一致
- [ ] 参数改为"0 警察 + 全员无武装"→ 必定沦陷；"500 警察 + 100% 武装"→ 必定清剿

### M2 · 真实城市（1 周）

**交付**：OSM 管线跑通，华盛顿特区 1km² 的真实建筑立起来，导航栅格可用，流场寻路正确（不会走进墙里）。

**验收**：
- [ ] 2,000+ 栋建筑，楼高与真实观感接近（人去楼不歪）
- [ ] 视觉上能认出这是 DC（街道格局对）
- [ ] 丧尸不会卡在墙角超过 3 秒

### M3 · 表现层（1–1.5 周）

**交付**：VAT 角色 + LOD + 假阴影 + 昼夜 + 粒子 + 血渍 + 后处理 + 三种视角。

**验收**：
- [ ] 街景视角（离地 2m）下角色动作自然，无"滑冰"
- [ ] 夜间窗光随机点亮且不闪烁
- [ ] 热成像能一眼分辨"潜伏感染者"
- [ ] 60fps 不掉

### M4 · 音频 + 导演 + 干预（1 周）

**交付**：空间音效、镜头导演、空袭/伞兵/直升机、慢放。

**验收**：
- [ ] 一次空袭有"哨音 → 爆炸 → 耳鸣 → 烟尘"的完整链路
- [ ] 导演模式连续看 3 分钟不觉得无聊（最重要的主观验收）

### M5 · 叙事与结算（1 周）

**交付**：单点卡片、名字/职业/家庭生成、行动后报告、曲线图、新闻标题。

**验收**：
- [ ] 随便跟一个小人 30 秒，能讲出一个"故事"
- [ ] 报告里的时间线与实际发生的事一致

### M6 · 回放与分享（3–5 天）

**交付**：种子 + 事件回放、时间轴拖动、IndexedDB 存档、URL 分享。

**验收**：
- [ ] 回放 20 分钟一局与原局逐帧一致（哈希校验）
- [ ] 刷新网页后能恢复上一局

### M7 · 打磨 + 2009 模式（1 周）

**交付**：复古点阵渲染器、原版 UI、Ruffle 彩蛋页、整体调优。

**验收**：
- [ ] Tab 一键在"2009"和"现代"之间切换，同一局同一时刻
- [ ] 复古模式下你能认出这就是当年那个游戏

## 17. 每日工作节奏建议

一个人做项目，最大的敌人是"三天没看见进展就放弃了"。建议：

- **每个 session 都以"能跑起来看到东西"结束**，不留半成品的破坏性重构。
- **每天先跑一遍确定性测试**（3 秒），保证昨天的改动没把地基弄坏。
- **做完一个里程碑就玩 10 分钟**，只玩不改。玩的时候记下"最烦的三件事"，那就是下个 session 的清单。
- **不要连续两天只写 UI 或只写 shader**，交替着写，保持新鲜感。
