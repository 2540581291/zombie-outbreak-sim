# 规划：混乱度能上也能下（v1 · 已实现）

> 起因：混乱值一旦涨上去就再也降不下来。
> 本文先核实「真实代码里有什么」，再给公式。**已按 S1–S3 落地**。

---

## 0. 现状（已核对代码，非推测）

公式在 `js/sim.js` 的「每秒一次」块里（约 2042–2070 行）：

```js
this.infectRate = (s.zombie + s.infected) / Math.max(1, this.pop0 || this.n);
this.awareRate = this.nAware / Math.max(1, this.n);
this.chaos = Math.min(CHAOS_W.cap, awareRate*100*0.5 + infectRate*100*2);
```

**为什么只升不降**：

| 输入 | 单调性 | 原因 |
|---|---|---|
| `awareRate` | 只升 | `setAware()` 里 `if (level <= this.aware[i]) return false`；`nAware` 只在新知晓时 +1，人死了也不减 |
| `infectRate` | 波动 | 分子是 `zombie + infected` —— 打死丧尸不会让它降 |

实测（每 tick 把丧尸清空、感染压到 0）：混乱 8 分钟从 5.2 涨到 35.4，因为知情率从 3.5% 涨到 70.9%（电话/网络继续扩散），而公式里没有任何衰减项。

## 2. 最终公式（四项彼此独立，不做互相乘的系数）

```
chaos = clamp( 知情项 + 感染项 + 事件热度 − 自然平静 , 0, 100 )

知情项   = awareRate × 100 × 0.5
感染项   = infectRate × 100 × 2
事件热度 = 会自己衰减的独立累计值（0–40）
自然平静 = 每游戏小时 +1 点，累计封顶 50 点
```

**事件热度**

| 来源 | 增量 | 挂点 |
|---|---|---|
| 每一枪 | +0.02 | `shoot()` |
| 平民死亡 | +0.5 / 人 | `killAgent()` |
| 新增感染 | +0.15 / 人 | `setInfected()` |
| 要员死亡 | +8（另加那 0.5 的平民死亡） | `killAgent()` 里 `vips` 判定 |
| 警局沦陷 | +6（每处每局一次） | 每秒块里 `policeNear(...,50) === 0` |
| **击杀丧尸** | **−0.6 / (平民人口/1000)** 每只 | `killAgent()` 的 `wasZombie` 分支 |
| 自然衰减 | τ = 90 秒（1.5 分钟减半） | 每秒块，`heat *= 1 − 1/90` |
| 上限 | 40 | — |

击杀按人口缩放的实测：20,000 人城市 → 每只 −0.03；杀 100 只 → 热度 −3。

**自然平静**

- 每游戏小时 +1 点（= 每 60 模拟秒 +1，一天 24 点）
- 累计**封顶 50 点**（`CHAOS_W.calmCap`），即"自然平静最多削掉 50 点混乱"
- 与知情、感染完全无关，是独立第四项

## 3. 实测

事件逐条验证（20000 人）：

```
击杀 100 只：heat 28.45 → 25.45   （−3.00 = 100 × 0.03）✓
平民死亡 +1：heat 25.45 → 25.95   （+0.50）✓
要员死亡  ：heat 25.95 → 34.45   （+8.5 = 8 + 该要员作为平民的 0.5）✓
自然平静  ：600 秒（=10 游戏小时）0.67 → 10.50  （+9.83 ≈ 每小时 1）✓
警局沦陷  ：50m 内警力清零后立刻 +6 并 pushEvent，flag 置 1（每处一次）✓
```

清空丧尸后（heat 自然衰减，知情继续扩散）：

```
T+60s   chaos 28.1  heat 24.4  calm 0.98
T+120s  chaos 18.4  heat 17.9  calm 1.93
T+180s  chaos 10.5  heat  9.1  calm 2.93
T+240s  chaos  8.3  heat  4.7  calm 3.93
T+300s  chaos 10.5  heat  2.4  calm 4.93   ← 热度见底，但知情率继续涨
T+420s  chaos 20.1  heat  0.6  calm 6.93
```

**结论**：事件热度能把它压下来（28 → 8）；但"知情率持续上涨"仍会把它顶回去——这是知情项本身的性质（你要求它独立、不乘系数）。长期看，自然平静涨到 50 后，`知情项 − 50` 正好抵消 100% 知情（50），届时混乱只剩感染项 + 热度。

## 7. 两边上限（增长与减少互不影响）

```
chaos = 钳( 增长合计 − 减少合计 , 0, 100 )
```

### 增长侧：合计 **200**

| 项 | 上限 |
|---|---:|
| 知情项 | **50**（100% 知情） |
| 感染项 | **100**（每 1% = 2 点，50% 感染顶满） |
| 事件热度 | **50** |
| **合计** | **200** |

事件热度按「每 1000 人口」换算（实际每次 = 数值 × 1000 / 人口）：

| 来源 | 每千人 | 2 万人地图 ≈ | 500 人地图 ≈ |
|---|---:|---:|---:|
| 枪声 | 0.4 | 每枪 +0.02（本项封顶 10） | 每枪 +0.8 |
| 平民死亡 | 10 | 每人 +0.50 | 每人 +20 |
| 新增感染 | 3 | 每人 +0.15 | 每人 +6 |
| 要员死亡 | 160 | 每人 +8.0 | 每人 +320 |
| 警局沦陷 | 120 | 每处 +6.0 | 每处 +240 |

### 减少侧：合计 **200**

| 项 | 上限 | 怎么达到 |
|---|---:|---|
| 自然平静 | **50** | 50 游戏小时（3,000 模拟秒 = 50 分钟 1×） |
| 击杀削减 | **150** | 每千人 0.6：50k 城 12,500 只 / 20k 城 5,000 只 / 2k 城 500 只 |
| **合计** | **200** | |

### 结论

- **两边都是 200**：清干净丧尸 + 平静攒满 → 混乱度可以降到 **0**
- 混乱度最大 100（钳位），增长 200 早已超过
- 事件按人口归一：500 人的地图死 1 个人 ≈ 5 万人地图死 100 个人
