# ZOS-R · 社会模拟扩展方案（v4 草案）

> 目标：把「一堆会跑的点」变成「一座真的在运转、然后在几十分钟里崩掉的城市」。
> 本文只做设计，不写实现。每条都标了**现状**、**做法**、**成本**、**验收**。

---

## 0. 一页纸结论

| # | 需求 | 现状 | 缺口大小 | 优先级 |
|---|---|---|---|---|
| 1 | 个体有目标：家 / 工作地 / 通勤 | 档案里只有**文字**（"托尔街 88 号"），没有坐标；人只是随机游荡 | ⭐⭐⭐ | P0 |
| 2 | **信息传播**（电话 / 网络） | 完全没有 | ⭐⭐⭐ | P0 |
| 3 | 爆发后行为分化（逃 / 守 / 找武器 / 找家人 / 去医院） | 只有 `FLEE`（80%）和"吓得腿软"（20%） | ⭐⭐⭐ | P0 |
| 4 | 地点属性（医院 / 警察局 / 学校…） | 只有建筑高度，没有 `amenity` 语义 | ⭐⭐⭐ | P0 |
| 5 | 武器系统（种类 / 熟练度 / 获取） | 只有"手枪"一种，出生自带，40 发 | ⭐⭐ | P1 |
| 6 | 感染与潜伏（零号病人 / 长潜伏 / 医院链） | 固定 8 秒潜伏，被咬就地转化 | ⭐⭐ | P1 |
| 7 | 社会功能（报警 → 警察出动） | 警察只在地图上随机巡逻 | ⭐⭐⭐ | P1 |

**总体判断**：1/2/4 是地基（数据和信息层），必须先做；3/7 是玩法（行为与响应）；5/6 是内容与叙事。
加起来大约是现有模拟内核工作量的 1.5–2 倍，建议分 6 期做，每期都能玩、都能测。

## 0.1 已拍板的决策（2025-10）

| # | 问题 | 决定 | 影响 |
|---|---|---|---|
| 1 | 医院定位 | **只聚集、不治疗**：早期人群往医院跑、在门口徘徊，然后医院变成传播热点 | 医院是"心理避难所"，不是补给点；真正的治疗只有玩家的「疫苗空投」 |
| 2 | 武器获取 | ① 正常情况**只有警察持枪**；② 家庭有枪的概率 `pGun`（面板可调，默认 12%），这类人**回家取**；③ 去警局的路线**只在感染率 > 20% 时解锁** | 开局街头几乎无枪；前 20% 是"人与尸"，过 20% 才开始有人抢警局 —— 秩序崩溃的分水岭 |
| 3 | 潜伏期 | **两套常量**：默认模式 = 现状 8 秒；**零号病人模式 = 长潜伏（10–30 分钟）**，且该模式下整条感染链都用长潜伏 | 其他 6 种模式的手感不变；只有零号病人是"温水煮青蛙" |
| 4 | 家人系统 | **做全**：每个人都在一个家庭里，家庭共享住址；成员关系（配偶/父母/子女）按年龄推断；少数是**旅客**（无家）或**独居** | 行为能"回家找家人"；失去家人会改变后续决策 |
| 5 | 枪声 | **要**：开火产生声音事件，半径内的丧尸被吸引过去 | 枪战会引出尸潮，"打完就跑"才有意义 |
| 6 | 玩家指挥 | **只能命令士兵**（伞兵/特警），不能命令警察 | 需要"选中单位 → 下达移动命令"的交互 |
| 7 | 警力投放 | 原来的「召唤警察」改成**调度**：从最近的警察局派人，**实打实走过去**；警察局有固定驻警数 | 没有瞬移；警局会被抽空 → 秩序崩溃看得见 |
| 8 | 随机性要适应地图 | POI **不能写死**：有 OSM 标签就用标签，没有就**按建筑存量推导**（数量按城市面积缩放、种子取自地图尺寸，同图稳定、换图自动变） | 换任何地图都有医院/警局，不会像镇平那样一个都没有 |
| 9 | 位置要合理 | POI **必须落在建筑轮廓内**（不在楼里的挪进去，挪不进去就丢掉）、**不能在水里** | 不会出现"医院在空地上""警局在河中央" |
| 10 | 坐标要统一 | 全线一套坐标：**x 东正、z 南正、网格第 0 行是南**；烘焙直接吐世界坐标，前端不翻符号 | 消灭"过边界就换算"这类错误源（POI 镜像、桥补丁判反都是它引起的） |

| 档案哈希生成（姓名/职业/住址） | `js/people.js` | **够用**：职业表 20 种、工作单位 14 个（含"夏里特医院""市立第三中学"） |
| 城市几何：建筑/道路/水系/绿地/桥 | `data/cities/<id>/city.json` | 缺 `amenity` 语义和街道名 |

### 缺的

| 缺口 | 影响 |
|---|---|
| 建筑没有 `amenity`（医院/警局/学校） | 无法做地点属性、无法让人"去医院/去警局" |
| 道路没有街道名 | 档案里的"托尔街 88 号"没法落到坐标 |
| 没有全局寻路（只有局部 Bug 绕障 + 门场） | "回家"这种长距离目标人走不到 |
| 没有社会层（家/工作/家人/信息） | 无法做动机与信息传播 |
| 没有事件系统 | 报警/出警/支援都无从谈起 |
| 武器只有一种 | 没有取舍，也没有"去警局拿枪"的意义 |

## 2. 你的需求（逐条展开）

### 2.1 个体目标：家 / 工作地 / 通勤

**你说的**：爆发前人应该有自己的目标 —— 有的在回家、有的在去上班。

**做法**

1. **给每个人两个坐标**：`home(x,z)`、`work(x,z)`（同住址的家庭共享 home，见 §3.1 家庭系统）。
   - 用 `people.js` 的同一套哈希（`h(i, salt)`）派生，保证"同一个人永远是同一个家"；
   - 落点用拒绝采样挑可走格（现有 `randWalk` 已经会挑可走格）；
   - 进阶：把 `home` 落到"建筑内部"，`work` 落到对应的 POI（护士 → 医院、教师 → 学校、店员 → 超市）。
2. **作息时间表**（游戏时间，一天 = 24 分钟，可调）：
   ```
   00:00-06:30 睡觉（在家，不动）
   06:30-07:30 通勤（家 → 工作地）
   07:30-17:00 上班（在工作地附近逗留 / 走动）
   17:00-18:00 通勤（工作地 → 家）
   18:00-23:00 自由活动（在家附近 / 商业区）
   23:00-24:00 回家
   ```
   - 退休 / 学生 / 自由职业用变体表（学生去学校，退休在公园/超市之间晃）；
   - **爆发后作息被打断**，转入 2.3 的行为决策。
3. **通勤怎么走**：见 §5 寻路三档。每天两次全员换目标，是寻路压力的峰值（2 万次寻路要摊到时间上：提前 10 分钟开始分批计算）。

**成本**：新数据 ~6 个 typed array，寻路是主要成本。
**验收**：随机抽 200 人，图上画出 home→work 的连线，全部落在可走格；通勤 30 分钟内能到达率 > 95%。

### 2.2 信息传播（电话 + 网络）—— 不是病毒，是**情报**

**你说的**：爆发后信息会通过电话和网络传播，人不该一直待在一个地方乱动。

**关键区别**：这条传播的是**"我知道出事了"**，不是感染。它决定"有多少人开始跑、往哪跑、去不去警局/医院"。

**做法**

1. **awareness（知晓度）**，每人一个字节，0–3：
   | 值 | 含义 | 触发 |
   |---|---|---|
   | 0 | 一无所知 | 默认 |
   | 1 | 听说（电话/网络/别人喊） | 传播 |
   | 2 | 亲眼看见 | 感知到丧尸 |
   | 3 | 亲身经历（被咬/家人被杀） | 事件 |
2. **三种渠道**：
   | 渠道 | 模型 | 成本 |
   |---|---|---|
   | 目击 | 现有感知半径内看到丧尸 → 2 | 0（复用感知） |
   | **电话** | 每个知晓者每 1–3 秒尝试打给"联系人"，成功则 +1 知晓度 | 低（队列） |
   | **网络** | 全局热度 `H`（0–1）随知晓人数上涨；每 2 秒按 `H` 广播给 K 个随机个体 | 低 |
   | 喇叭/警笛/广播 | 现有工具，确定范围强制提级 | 已有 |
3. **联系人不用建社交图**：用哈希确定性生成 —— 每人 2 个家人 + 2 个同事 + 1 个邻居（index 派生），传播时直接算。零存储。
4. **传播强度**与场景有关：
   - 距离越远越不知道（电话可以跨区，网络可以全城）；
   - 网络传播有"阈值效应"：知晓人数 > 3% 后热度暴涨（这就是"朋友圈刷屏"）；
   - 警察/士兵默认 awareness = 3（有电台）。
5. **反哺行为**：awareness 直接进 §2.3 的决策权重 —— 不知道出事的人照常上班（于是被咬），知道的人开始逃/回家/去警局。

**经验数据（用于校准）**：现代城市里，一起可见的暴力事件大致 3–10 分钟内被 30% 的人知道。
**验收**：爆发后画一条"知晓率曲线"，目标 5 分钟 30%、15 分钟 70%；上限定 90%（总有人不知道）。

### 2.3 爆发后的行为分化

**你说的**：有人往一个方向跑，有人固守原地；有人回家，有人去警察局找武器。

**做法**：把"看到丧尸就 80% 逃"升级成**目标制（Goal）+ 效用打分**。

目标表（第一版 8 个）：

| 目标 | 什么时候选 | 到达后 |
|---|---|---|
| `HOME`（回家找家人） | 家里还有活人、或家有枪（`pGun`）、或胆小 | 进屋；拿到枪则换装；家人跟着一起走 |
| `WORK`（去工作地） | 上班时段、家太远 | 进屋 |
| `FLEE`（逃向城外） | 无牵挂、或已经失去家人 | 往最近的图边跑，跑到边上算"逃离"（可计入已撤离） |
| `ARM_HOME`（回家拿枪） | 知道自家有枪（`pGun`）、且还没拿到 | 到家后换装，`skill` 按职业初值 |
| `ARM_POLICE`（去警局） | **感染率 > 20%** 才解锁 + 知道警局位置 + 胆子够大 | 到警局按库存换装 |
| `HELP`（去医院） | 自己/家人受伤或发热；**医院不会治好任何人** | 在门口等待/徘徊，成为传播热点 |
| `HOLD`（固守） | 胆小 + 在自己家附近 | 原地小范围躲，遇尸再逃 |
| `FOLLOW`（跟着人群） | 无明显偏好 | 跟随附近多数人的移动方向 |
| `MOVE_TO`（被指挥） | **玩家下达的命令（仅士兵）** | 走到点后原地戒备，射击半径内丧尸 |

**决策怎么打分**（每 1–2 秒一次，分帧计算）：

```
U(goal) = w1·安全(距最近丧尸)
        + w2·信息(awareness × 该目标是否已知可行)
        + w3·距离(1/(1+d))
        + w4·家庭(有家人在那？)
        + w5·性格(勇敢/胆小, 由 index 哈希固定)
        + w6·从众(附近同选择人数)
        + 噪声
```

- 权重可在参数面板暴露 2–3 个（"恐慌度""利他度""从众度"），玩家调一下就能看出不同社会反应；
- **性格**用哈希固定：`brave ∈ [0,1]`，影响 ARM/HOLD 占比；
- 决策结果写 `goal`（Uint8）+ `goalX/goalZ`，只在目标变化时重新寻路。

**防死锁**：同一目标连续 15 秒没有靠近（距离没变）→ 强制换目标（`FLEE`），并记一次"迷路"计数。
**验收**：爆发 1 分钟后抽样统计目标分布，例如 逃 40% / 回家 22% / 固守 15% / 警局 8% / 医院 7% / 跟随 8%，且"原地抖动"人数 < 2%。

### 2.4 地点属性（POI）

**你说的**：不同地方聚集的人不同，警察局有人有装备，医院有病人。

**做法**

1. **烘焙**：扩展 `pipeline/bake_pbf.py`，从 OSM 标签里抽 POI：
   | OSM 标签 | kind | 游戏语义 |
   |---|---|---|
   | `amenity=police` | `police` | 枪械库 + **固定驻警数**（`garrison`）+ 出警 / 调度的起点 |
   | `amenity=hospital` / `clinic` | `hospital` | **只聚集、不治疗**（决策 1）：早期人群往医院跑，然后变成传播热点 |
   | `amenity=fire_station` | `fire` | 消防（可做救援，暂缓） |
   | `amenity=school` / `university` | `school` | 学生聚集（人口稠密传播快） |
   | `shop=supermarket` / `amenity=marketplace` | `market` | 物资、人群 |
   | `railway=station` / `public_transport=station` | `transit` | 人流枢纽（爆发扩散快） |
   | `amenity=pharmacy` | `pharmacy` | 药 / 疫苗 |
   | `building=government` / `office=government` | `gov` | 避难所 |
2. 输出到 `city.json` 的 `pois: [{k, x, z, n, a, i}]`（`i=1` 表示是推导出来的，不是 OSM 标签）。
   **没有标签的地图**（中国城市常见）按建筑存量推导：目标数量按面积缩放，从楼里挑，位置取多边形内部点；
   种子取地图尺寸的哈希 → 同一张图永远同一批 POI，换图自动重排。
3. **两条硬性不变量（决策 8/9）**：
   - POI 必须落在某栋建筑轮廓内 —— 不在楼里的挪到 160m 内最近的楼，连楼都没有就丢掉；
   - 不能在水里（来自建筑，天然成立）。
3. **人群分配**：职业 → POI 类型（护士→hospital、教师→school、店员→market…），没有匹配的就用普通建筑当工作地。
4. **容量**：每个 POI 有 `cap`（人数上限），超过后"挤不进去"，人群在门口聚集 —— 这本身就会造成踩踏/传播。
5. **装备库**：`police` 有枪械清单，`pharmacy`/`hospital` 有疫苗清单，取用即可（和现有 tools 的"疫苗空投"打通）。
6. **医院的特殊性（决策 1）**：医院**不提供任何治愈**，它只是一个"人愿意往那儿跑"的地方。
   - 受伤/发热的人把它当避难所 → 在门口徘徊（`HELP` 目标到达后就地停留）；
   - 停留的人越聚越多 → **传播系数 ×2**（同格密度高）→ 医院很快变成最大的感染簇；
   - 唯一的"治疗"仍然来自玩家的「💉 疫苗空投」，而且只对**潜伏期**的人有效（现状如此，不改）；
   - 这样医院就自洽了：**它是希望的象征，也是爆发的加速器**。
7. **警察局是有编制的（决策 7）**：每个 `police` POI 记两样东西 —— `garrison`（驻警人数，默认按 POI 面积 8–20 人）
   和枪械库存。**派出去一个人就少一个**，驻警打光就空了。全城警力耗尽之后，报警不再有人来（见 §2.7 / §2.8）。

**成本**：烘焙脚本 + 一次重烘 5 个城市（~2 分钟），数据 +几十 KB。
**验收**：`node tools/test_poi.mjs` 断言每类 POI 数量 > 0 且都在可走格上；随机抽 5 个 POI 截图核对位置。

### 2.5 武器系统

**你说的**：现在只有手枪、出生自带；希望有手枪/大口径/左轮/霰弹枪/步枪/火箭炮，还有熟练度和准度。

**做法**：新建 `js/weapons.js`（纯数据表）+ `sim.js` 里 3 个数组（`wpn`、`mag`、`ready`）+ 熟练度 `skill`。

| 武器 | 伤害 | 射速 | 射程 | 弹匣 | 备弹 | 基础精度 | 噪音 | 备注 |
|---|---|---|---|---|---|---|---|---|
| 手枪 9mm | 5 | 0.45s | 26m | 15 | 45 | 0.55 | 90m | 警察标配 |
| 大口径手枪 .45 | 8 | 0.55s | 28m | 8 | 24 | 0.50 | 100m | 后坐大 |
| 左轮 .357 | 12 | 0.85s | 32m | 6 | 18 | 0.60 | 110m | 慢但稳 |
| 霰弹枪 | 5×6 弹丸 | 1.1s | 18m | 6 | 18 | 0.65（近）/0.3（远） | 140m | 近距清场 |
| 冲锋枪 | 4 | 0.10s | 24m | 30 | 90 | 0.42 | 120m | 泼水 |
| 步枪 | 9 | 0.30s | 60m | 30 | 90 | 0.62 | 150m | 士兵/猎人 |
| 狙击枪 | 25 | 1.8s | 120m | 5 | 15 | 0.80 | 170m | 一枪一个特感 |
| 火箭筒 | 120（范围 12m） | 3.5s | 90m | 1 | 1 | 0.85 | 300m | 误伤平民，慎用 |
| 燃烧瓶 | 火区 8s | 2.5s | 20m | 1 | 3 | 0.55 | — | 土制，便宜 |

- **熟练度 `skill` 0–1**：实际精度 `= 基础精度 × (0.55 + 0.45·skill)`；装填时间 `× (1.3 − 0.4·skill)`；满熟练 = 表值。
  职业给初值：警察 0.6、士兵 0.8、猎人 0.7、普通市民 0.25。
- **获取途径（决策 2 改定）**：
  | 谁 | 开局持枪？ | 之后怎么拿枪 |
  |---|---|---|
  | 警察 | ✅ 手枪 + 霰弹枪（按警局库存） | — |
  | 士兵 / 特警 | ✅ 步枪 / 冲锋枪 | — |
  | 普通平民 | ❌ **开局一律徒手** | ① **回家取**（自家有枪才成立）；② 感染率 > 20% 后**去警局抢** |
  | 武装平民 | ❌ 不再"出生自带"（这是本次最大的手感变化） | 同上 |

  - **家庭持枪率 `pGun`**（面板可调，默认 12%）：由个体下标哈希决定"这一家有没有枪"，所以同一个家庭永远是同一个结论；
    本人**知道自己家有没有枪**（信息不对称：玩家得看档案才知道）；
  - 原来的「平民武装率」滑块含义改成 **`pGun`**，默认值从 10% 调到 12%（开局街头几乎无枪，
    有枪的人也散落在各处，要回家才能拿到 —— 这正是"爆发初期只能跑"的原因）；
  - 弹药：`mag`（弹匣内）+ `reserve`（备弹），打空要装填（`reload` 状态）。

- **感染率阈值（决策 2 的开关）**：
  ```js
  // 每秒算一次，代价可忽略
  const rate = (stats.zombie + stats.infected) / Math.max(1, pop0);
  const martialLaw = rate > 0.20;    // 20% 之后，平民才敢/才想到去警局
  ```
  - `rate ≤ 20%`：平民只有"回家取枪"这一条路，警局只是警察的据点和人群的避难所；
  - `rate > 20%`：`ARM_POLICE` 解锁，胆子大的平民开始往警局涌（**这时候警局门口会堵人**，也被尸群盯上）；
  - 面板上暴露一根"戒严阈值"（默认 20%），方便调节奏。
  - 这条阈值同时给事件系统用：跨过 20% 时打一条战报里程碑「秩序崩溃」。
- **噪音**：开枪生成"声音事件"，半径内的丧尸被吸引（成本很低，效果极好，建议做）。

**成本**：数据表 + 3 个数组 + 开火/装填分支 + 5 个工具/单位的映射。
**验收**：`node tools/test_weapons.mjs` 断言每种武器的 DPS/弹匣/装填时序；警局取枪后命中率变化符合公式。

### 2.6 感染与潜伏（零号病人）

**你说的**：被感染后可以有很长的潜伏期；喝水感染的；之后去医院，长时间潜伏后爆发，形成自然的爆发逻辑。

**做法**

1. **感染途径**（新增两种，现有咬伤保留）：
   | 途径 | 触发 | 概率 |
   |---|---|---|
   | 咬伤 | 现有 | 100%（猫狗 45/60%） |
   | **水源** | 在水体附近停留 / 喝水（低频） | 极低（0.1%/分钟），零号病人模式里作为"源头" |
   | 飞沫/密闭 | 同一建筑内、通风差 | 低（0.5%/分钟） |
2. **三阶段感染**（新增 2 个状态）：
   ```
   SUSCEPTIBLE → INCUBATING（潜伏：无症状，几乎不传染，正常作息）
               → SYMPTOMATIC（发病：发热/虚弱，去医院，低传染）
               → ZOMBIE
   ```
   - `INCUBATING` 用现有 `timer`，**两套常量（决策 3）**：

     | 模式 | 潜伏时长 | 用途 |
     |---|---|---|
     | 其余 6 种模式 | **8 秒**（现状，不变） | 快节奏、看曲线 |
     | **零号病人** | **10–30 分钟**（游戏时间），整条感染链都用 | 慢节奏、看"社会如何一步步崩" |

     常量放在 `INCFG = { quick: 8, long: [600, 1800] }`，由模式决定用哪套；
   - `SYMPTOMATIC` 的行为：去 `hospital`（HELP 目标），走路变慢、被丧尸更容易追上；
   - **医院治不好人（决策 1）**：到了医院只是"停在门口"，于是医院聚集 → 传播加速 → 院内/门口爆发；
   - 潜伏期在个体身上"不可见"，只有档案里能看到（信息不对称，玩家只能通过行为猜）。
3. **零号病人模式**：
   - 开局 1–3 人 `INCUBATING`，**不显示任何可见提示**（不渲染成变色，只体现在行为上）；
   - 感染源叙事：水源污染 / 外来输入（可在事件流里写一句"某处水质异常"）；
   - 20–40 分钟自然爆发（取决于潜伏时长、医院聚集、人口密度）；
   - 与现有 `?mode=` 的六种模式并列成第 7 种。

**成本**：状态机 2 个新状态 + 传染途径 + 医院链。
**验收**：`node tools/test_patientzero.mjs`：0 号病人 3 人开局，断言 30 分钟内丧尸数从 0 涨到 > 100，且首次爆发点与医院 POI 的距离 < 200m 的比例 > 50%。

### 2.7 社会功能：报警 → 出警

**你说的**：爆发后有人报警，警察应该从警察局过去。

**做法**：一个轻量**事件系统**（Event）+ **响应者**（Responder）。

```
event = { id, kind: 'attack'|'sighting'|'fire'|'injury', x, z, t, sev, src, ack, responders[] }
```

1. **产生**：目击者（awareness ≥ 2）有 85% 有手机，每 3–8 秒尝试报警一次（避免刷屏），同一区域 60 秒内只报一次（合并）。
2. **接警**：最近的 `police` POI 收到事件 → **从驻警里点名**（`garrison--`）→ 在警局门口生成 →
   寻路到现场。玩家手动「调度」走的是**完全同一段代码**（`dispatch(poi, x, z, n)`），
   所以"玩家派的警"和"自动出警"行为一致，只是触发者不同。
3. **到场**：`POLICE` 状态 + 现有射击逻辑，射击目标从"最近的丧尸"改为"事件点附近"。
4. **升级**：事件数量/severity 累积 → 触发更高等级响应（特警 → 军队）；这和现有「经费 + 工具」打通 —— 玩家是"上级"，自动响应是"下级"，两者互不冲突。
5. **失败模式**：警员全灭 → 该 POI 库存清零 → 后续报警无人响应（这就是"秩序崩溃"的可视化）。

**成本**：事件队列 + POI 响应者 + 少量状态。
**验收**：`node tools/test_response.mjs`：制造一次报警，断言 60 秒内有警员到达（路径可达时）；警员死亡后库存下降且不再出警。

### 2.8 玩家指挥（调度 + 命令士兵）

**你说的**：底部原来那个"召唤警察"改成"调度"，从警察局派人、真的走过去；只有士兵能被命令。

**做法**

1. **警力调度（替换现有「🚓 警察小队」）**
   - 选工具 → 点地图 = 目标点；
   - 系统找**最近的、还有驻警的警察局**，派 N 名（默认 6）；
   - 警员在**警局门口**生成（复用 `addUnit`），然后**寻路走过去**：耗时 = 距离 / 速度（2.3 m/s），**没有任何瞬移**；
   - 到达后进入"现场处置"：向事件点附近的丧尸开火，30 秒后转入巡逻；
   - 费用按距离算（¥30,000 起 + 每 100m ¥2,000），冷却 6 秒；
   - 没有可用警局（都空了 / 太远）→ toast：「附近警局已无可用警力」。
2. **命令士兵**
   - 左键点士兵（或拖框多选）→ 选中；
   - 右键点地面 = 「移动到」，`Shift` + 右键 = 追加路点；
   - 士兵 `goal = MOVE_TO`，寻路走过去，到达后原地戒备（射击半径内丧尸）；
   - **只对士兵（伞兵班 / 特警）生效**；点警察只会显示档案，不能下令 —— 这是你定的规则；
   - 下令不花钱（人已经在场上），但士兵只能靠空投补充，用一次少一次。
3. **为什么这样设计**
   玩家从"点一下就变出警察"变成"警力的调度者"，警察局变成真正的战略资源：
   **保住警局 = 还有出警能力；警局被占 / 警力打光 = 城市进入无政府状态。**
   而且它和 §2.7 的自动出警是同一段代码，不会出现"玩家派的警很聪明、自动派的很蠢"的割裂。

**成本**：调度复用 §2.7 的 `dispatch()`；命令系统 = 选中 + 目标点 + 一次寻路。
**验收**：`node tools/test_dispatch.mjs` —— 调度 6 人后警局驻警 −6；警员从警局出发、60 秒内到达 800m 外的目标点；驻警为 0 时调度失败并提示。

## 3. 我补充的 5 个设计

### 3.1 家庭系统（做全，但仍是零图谱）

**做全的意思**：除了少数旅客和独居者，每个人都在一个家庭里，家庭共享住址，成员之间有真实关系（配偶 / 父母 / 子女）。
难点是 2 万人不能存一张任意图。解法：**家庭 = 索引上的连续区间**。

1. **分组**：按顺序切块，块大小按分布抽（哈希决定）——
   1 人（独居）10% / 2 人 30% / 3 人 28% / 4 人 22% / 5 人 10%。
   于是"某人的家人"= 自己所在区间里的其他下标，**不需要存边**；
   `hh`（Uint16 家庭 id）+ `hhStart/hhEnd`（家庭 id → 区间），约 6.6k 个家庭、26 KB。
2. **住址共享**：同一个家庭用**同一个 home 坐标**（同一栋楼，±3m 抖动），所以"回家"是真的回到自己家。
3. **姓氏共享**：姓氏从家庭 id 取（一家人同姓），名字仍从个体下标取 —— 档案里"米勒一家"是自洽的。
4. **关系推断**（看年龄，不存字段）：家庭内按年龄排序 →
   - 最年长两位成年且年龄差 < 15 → **配偶**；
   - 未满 18 岁 → **子女**；
   - 三代同堂：最年长 > 60 且有中间代 → 祖父母。
   档案里显示"配偶：安娜·米勒 / 子女：卢卡斯·米勒（9 岁）"，全部现算。
5. **两类例外**：
   - **旅客** 3%：没有家（住旅馆 POI 或地图外），没有家人；行为是"往车站/旅馆跑，然后往地图边缘跑"；
   - **独居** 10%：单人家庭，没有家人，行为上更倾向 `FLEE`（没有牵挂）或 `HOLD`（守着家）。
6. **行为怎么用**：
   - `HOME` 目标 = **回家找家人**：家人还活着 → 到家后"团聚"（家人跟着家长走，形成 2–5 人的小队）；
   - 家人死亡 → `brave` 下降 20%、目标立即重算（大概率转 `FLEE` 或 `ARM`）→ 这就是"心态崩了"；
   - 电话传播时**优先打给家人**（联络概率 0.8，同事 0.4，邻居 0.3）。
7. **成本**：3 个数组（26 KB）+ 分组一次 O(n)；查询"某人的家人"= 区间遍历（≤5 人）。
   **收益**：真实家庭、确定性、可测试，且不需要图结构。

### 3.2 目标（Goal）显式化

现在的状态机是"状态驱动"，加了社会层后建议改成 **目标驱动**：
`goal`（去哪）+ `state`（身体状态），两个正交。
好处：目标可以变（回家 → 遇到尸群 → 逃），状态也可以变（跑 → 被咬 → 潜伏），组合数可控。

### 3.3 事件总线（Event Bus）

所有"社会性的事"走同一条队列：报警、目击、医院收治、警局出警、玩家投放。
这样：① UI 能统一显示"正在发生什么"；② 战报时间线自动丰富；③ 测试可以只测队列。

### 3.4 群体行为（低成本版）

- **从众**：邻域内方向平均 × 权重，0.3 秒更新一次（复用空间哈希）；
- **拥堵**：同 1m 格人数 ≥ 3 → 速度 ×0.5（人流堵在门口/桥上，很真实）；
- **踩踏**（可选）：死胡同里人数 > 8 且有人感染 → 小范围伤害。

### 3.5 观察界面（信息不对称的乐趣）

- 顶栏加一根**"信息热度"**条（0–1）；
- 地图上加**事件标记**：报警点（红圈闪烁）、警局出动（蓝箭头）、医院聚集（红十字变大）；
- 个体档案扩展：`目标`、`武器/熟练度`、`知晓度`、`家人状态`、`潜伏倒计时（仅玩家可见）`；
- 总览表加列：目标、武器、知晓度。

## 5. 寻路（这是最大的工程风险）

三档，按需升级：

| 档 | 做法 | 成本 | 用在哪 |
|---|---|---|---|
| **A. 直线 + Bug 绕障**（现在就有） | 目标点直走，撞墙沿墙滑 | ≈0 | M1 先用；近距离（< 120m） |
| **B. 局部 A*（8m 格，半径 60m）** | 只在卡住 > 1 秒时算一次，结果缓存 5 秒 | 每次 ~0.1ms，限 20 次/帧 | 城里穿院子的短途 |
| **C. 道路图 A*** | 从 `city.roads` 建图（交叉口=节点，路段=边），A* 出折线，个体沿折线走 | 每次 ~0.3–1ms，限 10 次/帧 + 缓存 | 通勤、跨区（> 120m） |

关键优化：**同目标共享**。所有人去同一个医院/警局 → 只算一条主路径，个体从最近的主路径节点切入（相当于给 POI 做"汇集流"）。

## 8. 验收与自检（每期都要过的门）

1. **确定性**：同一 seed 同参数两次运行，`px/state/aware` 哈希一致（现有 `test_sim` 的做法）。
2. **性能**：20k 个体 tick ≤ 4ms（现在是 1.5ms）。
3. **不倒退**：现有 25 个测试全绿；「站在墙里的活体 = 0」这条不能破。
4. **分布合理**：爆发 1 分钟后目标分布符合预期区间（见 §2.3），且"原地抖动" < 2%。
5. **可视化**：新系统都要能在 HUD/地图上看见，否则无法调参（这也是本项目一直的做法）。

## 9. 风险与取舍

| 风险 | 说明 | 缓解 |
|---|---|---|
| **成本爆炸** | 寻路是最贵的，2 万人同时换目标会卡 | 三档寻路 + 分帧 + 同目标共享 |
| **"全体做同一件事"** | 效用函数容易让所有人同时逃向同一边 | 加入性格/家庭/信息差异 + 噪声，并用分布测试卡住 |
| **平衡被打破** | 社会层让人更早逃、更快死，疫情曲线会变 | 保留"纯快速模式"（现在的行为）作为对照基线 |
| **医院悖论** | 医院既治病又是热点，容易变成"必死点" | 治疗量与感染率可调，先做成"放大器"再调 |
| **数据质量** | OSM 的 `amenity` 在非欧洲城市覆盖差（郑州/南阳） | POI 缺失时退化成"普通建筑"，不报错 |
| **可测性** | 系统越多越难定位问题 | 每个系统一个独立测试脚本 + 事件队列可日志回放 |

## 附：与现有"档案"的衔接（这就是我为什么先看 `people.js`）

`profileFor()` 现在已经能给出：姓名 / 年龄 / 性别 / 职业 / 住址文字 / 工作地文字 / 家庭情况。
其中 **职业（20 种）和工作单位（14 个，含医院/中学/大学/药店）** 可以直接映射到 POI 类型：

```
护士 → hospital     教师 → school      店员 → market
地铁司机 → transit   药剂师 → pharmacy  会计/工程师 → office（普通建筑）
退休 → 家/公园       学生 → school
```

也就是说：**M1 的数据不需要凭空造**，只要把"文字"变成"坐标"，人就立刻有了社会属性。
