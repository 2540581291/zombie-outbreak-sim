# 尸变链条怎么接进我们这套引擎 · 设计方案（未改游戏）

> 目标：把原版 2009 的 `walk → 被咬 → turn01 / die01 → zrise01 → zwalk` 四段动画链，
> 接到 `js/sim.js` 的 SoA 模拟 + `js/retro.js` 的实例化图集渲染上。
> 约束：**不改 `state` 语义**（它现在承担"社会身份 + 计数 + 配色"，动它等于全库重写）。
> 现状：本文只出设计与原型，`proposal/` 下的代码**没有**被 `index.html` 引入。

---

## 0. 结论

1. **数据不缺，缺的是"帧数正确"**。现在 `assets/retro/atlas.json` 里有 68 支动画，但 **39 支的帧数比原版少**（最多少 48 帧，police01 idle01 55→7），所以就算今天把状态机接上，`turn01` 也只有 37 帧、播 2.8 s 而不是 7.35 s。必须先从 `reference/core` 重建图集 —— 已核算：**2,728 帧、0 缺失**（`tools/plan_atlas_rebuild.py`）。
2. **状态机不用新增 `ST`**，加一个**正交于 state 的"动作阶段"**（`A.NORMAL/TURN/DIE/RISE`）+ 每体 4 个数组就够；`state` 继续表示"我是谁/算什么数"。
3. **原型已跑通**：`proposal/turnchain.js` + `proposal/test_turnchain.mjs`，10 项断言全过（两条路径、时间表、帧号、末帧定格）。接入时就是把它搬进 `sim.js` + 三处接线。

```
现在:  被咬 ──▶ INFECTED ──timer 到 0──▶ ZOMBIE          （瞬变，没有动画）
       中枪 ──▶ CORPSE                                 （瞬变，直接跳到 die01 末帧）

目标:  被咬 ──▶ INFECTED ──timer 到 0──▶ [turn01 7.35s] ──▶ ZOMBIE
       中枪 ──▶ CORPSE ──[die01 3.75s]──▶ 躺尸 ──死线到──▶ [zrise01 6.45s] ──▶ ZOMBIE
```

## 1. 现状盘点（对着代码看）

| 环节 | 我们的代码 | 原版 | 差距 |
|---|---|---|---|
| 状态集合 | `ST` 10 个：CIV/FLEE/FIGHT/POLICE/ZOMBIE/CORPSE/SOLDIER/INFECTED/SAVED/WILD（`sim.js:11`） | 14 个"位编码"状态，其中 6/7/8/9 是纯动画态 | 我们**没有动画态**，`state` 混了"身份"和"动作" |
| 感染到点 | `sim.js:1653-1668`：`timer<=0` → 直接 `state=ZOMBIE`（还顺手改 kind/spd/hp） | 先播 `turn01`（1.20~7.35 s，按体型），期间冻结，播完才变 | 缺一整段 |
| 死亡 | `sim.js:2312-2323` `killAgent()` → 瞬间 `CORPSE`；`strike()` 2356、`boomBurst` 2337 同 | 先播 `die01`（3.75~6.84 s），播完才进"尸体层" | 缺倒地过程 |
| 尸体 | `sim.js:1434` 尸体直接 `continue`，只画 `die01` 末帧 | 尸体是**可感染实体**（带 `Infectable`），死线到点播 `zrise01` 爬起来 | 尸体是死的，永不复活 |
| 咬死 | `sim.js:1740-1752`：被打死也设成 `INFECTED`（还活着的潜伏者），hp 补到 1 | 死了就是死了（尸体），只是尸变计时照走 | 语义相反，但**这恰好是我们要保的差异化**（见 §6） |
| 动画选择 | `retro.js:228-250` `_pickAnim(state)` 纯查表 | `_dw934.as:291-367` 每状态一支，且**时长=帧数×帧长** | 我们没有"状态时长"概念 |
| 帧号 | `retro.js:333` `phase[i]*len`（步态相位） | `(仿真时间-状态开始)/帧长`，一次性动画末帧定格 | 阶段动画不能靠步态相位 |
| 体型 | `retro.js:300-311` 渲染期按 `i` 哈希挑 | 生成时定 `_type`，**状态时长按体型** | 渲染管体型、模拟不知道 → 时长会突变（见 §4.5） |
| 剪影 | `retro.js:215-218` 单色绿（图集里烘死） | 绿/蓝/红三色阵营 | 见 §5.5 |
| 阴影 | 无 | 20×15 软椭圆，偏移 (-8,-2) | 见 §5.4 |
| 图集帧数 | 9,760 帧 / 2048×19520 / 5 套变体 | 2,728 帧（68 支 × 2 套贴图） | 帧数**不足**且**变体过多**（§3） |

用一行话说：**我们的引擎把"死"和"变"都做成了瞬时赋值，所以画面上一具尸体是"啪"地出现的。**

## 2. 数据层：先从 `reference/core` 重建图集

### 2.1 审计结果（这次跑出来的）

```
python tools/audit_atlas_vs_original.py
→ 68 支动画里 39 支的帧数和原版不一致（全部偏少）
   police01 idle01  55 → 7      police01 idle02  98 → 52
   guy01   turn01   49 → 37     guy01   idle02   43 → 14
   fat01   turn01   46 → 26     police01 turn01  40 → 26
   guy01   zrise01  43 → 37     police01 zrise01 52 → 44
   girl01  die01    25 → 9      girl02  die01    25 → 9
```

原因：早期批量导出时，SWF 里**被多支动画共用的帧**是以 `/_assets/<id>.png` 这种**无符号名路径**内嵌的（我们上次拆精灵链时才发现），按"符号名"去收集就会漏掉它们。

### 2.2 重建是可行的（已核算）

```
python tools/plan_atlas_rebuild.py
→ 136 个组合（68 支 × 实色/轮廓）、可解析帧 2,728、解析失败 0
→ 去重后不同图片 1,724 张、总像素 1.4 M px、单帧最大边长 300 px
```

解析办法（`tools/make_anim_figures.py` 里已经实现，直接复用）：

```python
# 帧序：动画类里的 _ir761() switch（帧号 → 静态变量名）
# 像素：静态变量的类文件里 [Embed(source="/_assets/xxx.png")]
#       若是 "/_assets/<符号路径>.png" 就直接按名取；若是裸 "/_assets/123.png" 就取 123.png
# 帧数：_qk83()；帧长：_br451()；循环：_wc1144()
```

### 2.3 打包方式要改两处

| 现在 | 建议 | 理由 |
|---|---|---|
| 固定 **64×64** cell | **变量矩形**（rect 里本来就存 w/h，shader 用 `aRect.zw`） | `shoot01` 单帧 300×14，64 的格子放不下；固定格子还会浪费 8~10 倍面积 |
| **5 套烘焙变体**（衣服配色副本） | **1 套实色 + 1 套白描边**，衣服差异交给现有 shader 的 `aHue` | 5 套是 ×5 的显存；`retro.js:386-388` 已经在逐体做色相偏移了 |

按变量矩形打 1:1 的包，2,728 帧 ≈ **2048×768（1.6 M px ≈ 6.4 MB RGBA）**；
现在这张图是 2048×19520 —— PNG 只有 751 KB（大片空 cell 压得好），但**上传后是 159.9 MB 显存**（RGBA8，实测 `assets/retro/atlas.png`）。
也就是说：**补全帧数反而能把显存占用砍到 1/25**，对核显是实打实的收益。

### 2.4 atlas.json 要加三个字段

```jsonc
{
  "cell": 64, "w": 2048, "h": 768,
  "anim_ms": { "guy01/turn01": 150, "police01/walk": 100, ... },   // 帧长，驱动帧号
  "anchor":  { "guy01/turn01": [22, 11], ... },                    // 可选：画布中心=人物中心，已实测偏差 <5px
  "frames":  { "guy01/turn01_solid": [[x,y,w,h], ...], ... }
}
```

`anim_ms` 是**必需**的，不然渲染层没法算"这一帧该在哪个 t 出现"（我们现在的 `FPS = 12` 是个假的全局常数，`retro.js:12`）。

## 3. 状态层：用一个正交的"动作阶段"

### 3.1 为什么不新增 `ST`

`ST` 现在被 40+ 处引用当"身份"用：配色（`colorClassOf`）、计数（`stats.civ++/infected++`）、目标筛选（`st !== ST.CORPSE`）、音效。加 `ST.TURNING` 会牵动每一处 `switch(st)`，而且 `INFECTED→TURNING→ZOMBIE` 期间"身份"其实没变（他还是平民）。

所以加一个**只影响三件事**的字段：**能不能动 / 画哪支动画 / 多久**。

```js
export const A = { NORMAL: 0, TURN: 1, DIE: 2, RISE: 3 };
```

### 3.2 数据结构（5 个数组，62k 体 ≈ 0.85 MB）

```js
export function attach(sim) {
  const n = sim.state.length;
  sim.aStage = new Uint8Array(n);     // A.*
  sim.aT     = new Float32Array(n);   // 阶段已过时间（跟 sim.time 同源，单位秒）
  sim.aDur   = new Float32Array(n);   // 阶段总时长（由体型决定）
  sim.aZ     = new Uint8Array(n);     // 这段动画是不是丧尸版（zdie/zrise）
  sim.riseAt = new Float32Array(n);   // 尸变死线（绝对时刻）
  if (!sim.body) sim.body = new Uint8Array(n);   // 体型：渲染和时长共用（见 §3.5）
  // 注意：sim.reset()/种子重开时 riseAt 也要 fill(0)，否则旧死线会立刻把新尸体拉起来
}
```

### 3.3 三个接线点（就是全部改动）

**① 感染时**：5 处 `state=INFECTED`（`sim.js:607/674/1742/1748/2337`）统一走一个函数，顺便记死线：

```js
// 原版用的是"首次被咬时刻 + 感染时长"的绝对值，不是倒计时。
// 这样倒地动画期间这条时钟"照走"，不需要谁去减它 —— 也就不会出现
// "躺下后还要再等一遍感染时长"的 bug。
// 作为 Sim 的方法（proposal/turnchain.js 里是自由函数，接入时挂到类上）
setInfected(i, seconds) {
  this.timer[i]  = seconds;              // 保留：现有 sick/panic 逻辑在用
  this.riseAt[i] = this.time + seconds;  // 新增：绝对死线
  this.state[i]  = ST.INFECTED;
}
```

**② 潜伏到点 / 尸体到点**（原 `sim.js:1653` 那段搬家）：

```js
case ST.INFECTED: {
  sim.timer[i] -= cdt;
  ...
  if (this.time >= this.riseAt[i]) {     // ← 换掉 `timer<=0`
    this.beginTurn(i);                   // 站着转身，7.35 s 后变丧尸
  }
  break;
}
```

```js
// 原来 sim.js:1434 是 `if (st===CORPSE||st===SAVED) continue;`
// 要把尸体拆出来，给它一个很便宜的 tick：
if (st === ST.CORPSE) {
  if (this.aStage[i] !== A.NORMAL) { this.tick(i, cdt, ON_STAGE_DONE); continue; }  // 正在倒地/爬起
  if (this.riseAt[i] > 0 && this.time >= this.riseAt[i]) { this.riseAt[i] = 0; this.beginRise(i); }
  continue;
}
```

**③ 死亡**（`killAgent` / `strike` / `boomBurst` 三处）：

```js
killAgent(i, by) {
  const wasZombie = (SPECIES[this.kind[i]].team === TEAM.ZOMBIE);
  ...
  this.state[i] = ST.CORPSE;
  this.beginDie(i, wasZombie);   // ← 新增这一行（其余保持）
}
```

**完成回调**（一处）：

```js
onStageDone(stage, i) {
  if (stage === A.TURN || stage === A.RISE) this.becomeZombie(i);   // = 原 1653-1668 那段
  // DIE 播完什么都不用做：人已经躺在尸体层，画的就是 zdie01/die01 的末帧
}
```

### 3.4 冻结：哪些循环要加 `if (blocked) continue`

原版在状态 6/7/9 上把 `Moving / LiveHuman / Infectable` 位全清了，所以那些人不移动、不被咬、不被选为目标。我们是显式判断：

| 位置 | 加什么 | 为什么 |
|---|---|---|
| `step()` 主循环开头（`sim.js:1432`） | `if (blocked(i)) { tick(i, cdt, onStageDone); continue; }` | 一站住就什么都不做 |
| 丧尸找目标 `findNearest` 的目标筛选（`sim.js:1294` 附近） | 排除 `blocked` 的 | 不许咬正在变的人（原版状态 6 没有 `LiveHuman`） |
| 咬合判定（`sim.js:1720` `if (cs === ST.CIV ...)`） | 同上 | 同 |
| 命中/爆炸（`hurt`、`strike`） | 建议**允许**伤害但不再触发新阶段 | 免得"打到一半不死了" |

### 3.5 体型必须从渲染层搬进模拟层（关键耦合）

现在体型是在渲染时按 `i` 哈希挑的（`retro.js:300-311`），而**原版的阶段时长是按体型的**（`turn01`：guy01 7.35 s、guy02 1.20 s、fat01 6.90 s）。如果模拟层不知道体型，只能用一个平均时长，会出现"胖子 2 秒就变完、瘦子 7 秒"的视觉不一致。

```js
// 出生时定一次，渲染和模拟都用它
sim.body[i] = CIV_BODIES[h % CIV_BODIES.length];      // 渲染层读 sim.body[i]，不再自己算
```

同理，丧尸体型（`ZOMBIE_BODIES[i % 4]`）也搬过来 —— 现在它依赖 `i` 的奇偶，重建/回收个体后体型会变。

## 4. 渲染层改动

### 4.1 `_pickAnim` → `animFor`（阶段优先）

```js
// retro.js：在原有 _pickAnim 前面插三层
const stage = sim.aStage[i];
if (stage === A.TURN) return 'turn01';
if (stage === A.DIE)  return sim.aZ[i] ? 'zdie01' : 'die01';
if (stage === A.RISE) return 'zrise01';
// 其余照旧（CORPSE 且 stage=NORMAL 时仍是 die01/zdie01 的末帧）
```

### 4.2 帧号：阶段动画用 `aT`，不用步态相位

```js
const ms = this.meta.anim_ms[key];                 // 新增字段
let fi = frameOf(sim, i, frames.length, ms);        // 阶段动画：clamp(t/ms, 0, n-1)
if (fi < 0) fi = Math.floor(sim.phase[i] * frames.length) % frames.length;   // 原来的逻辑
if (st === ST.CORPSE && sim.aStage[i] === A.NORMAL) fi = frames.length - 1;  // 躺尸定格
```

> 一个必须注意的点：`sim.step()` 的 `far` 分支用 `cdt = dt*4`（`sim.js:1442`）。**阶段推进必须用 `cdt`**，否则远处的人在"变"的时候会比近处慢 4 倍。这个坑原版没有（它没有 LOD），我们必须要处理。

### 4.3 尸体层：一个 y 偏移就够

原版是两张 `BitmapData` 分层（`_dw934.as:130-134`）。我们的 sprite 是带深度测试的实例化 quad，直接**把尸体压低 0.15 m** 就有同样的分层效果：

```js
dummy.position.set(x, sim.state[i] === ST.CORPSE ? 0.45 : 0.6, z);
```

（如果以后尸体要压住活人，再改成两个 InstancedMesh，代价是 +1 draw call。）

### 4.4 阴影 pass（新增 1 个 InstancedMesh）

原版参数（`_dw934.as:89-91, 368-387`）：贴图 20×15 软椭圆、颜色近黑、alpha 最大 60%、**中心相对人物 (-8, -2) 像素**、**不随朝向旋转**、先画。

```js
// 换算：1 px = M_PER_PX = 0.11 m（retro.js:11）
const SHADOW_DX = -8 * 0.11;   // -0.88 m  → 世界 X
const SHADOW_DZ = -2 * 0.11;   // -0.22 m  → 世界 Z（符号接入时实拍确认）
```

```js
// 单独一张 32×32 的小贴图，单独的材质：alpha 混合必须开，
// 不能复用主材质（主材质 discard<0.45 + 不透明，会把阴影切成硬边）
const smat = new THREE.ShaderMaterial({
  uniforms: { uTex: { value: shadowTex } },
  transparent: true, depthWrite: false, depthTest: true,
  vertexShader: `... varying vec2 vUv; ...`,              // 实例矩阵 + 贴图 uv
  fragmentShader: `... vec4 t = texture2D(uTex,vUv); gl_FragColor = vec4(0.07,0.07,0.07, t.a*0.6); ...`,
});
this.shadowMesh = new THREE.InstancedMesh(sgeo, smat, CAP);
this.shadowMesh.renderOrder = 1;      // 在人物（默认 0）之前
```

开关条件（照抄原版的"不该有阴影"的两条）：

```js
const noShadow = sim.state[i] === ST.CORPSE || wantOutline || naturalPx < 3;
```

### 4.5 三色剪影：把 outline 烘成**白**，再用 tint 上色

原版三色（实测像素）：平民 `#40D43B`、警察 `#1212FF`、丧尸 `#E30000`。我们图集里的 outline 是**烘死的绿**，没法变色。

改法很小：重建图集时把 outline 帧的 RGB 全写成白（alpha 不动），渲染时：

```js
const SIL = { human: [0.25, 0.83, 0.23], police: [0.07, 0.07, 1.0], zombie: [0.89, 0, 0] };
// outline 分支
tints[k*3] = c[0]; tints[k*3+1] = c[1]; tints[k*3+2] = c[2];  // c = SIL[阵营]
hues[k] = 0;                                                   // 关掉衣服换色
```

白像素在现有 shader 里 `sat≈0` → `cloth=0`、`skin≈0`，所以 `col*vTint` 出来就是纯阵营色，**shader 一行都不用改**。

### 4.6 圆点档：阶段中的人不能被降级

`retro.js:343` 在 `naturalPx < DOT_BELOW_PX` 时改画圆点。远看时正在尸变的人如果变成圆点，"变"这件事就看不见了。建议：

```js
if (naturalPx < DOT_BELOW_PX && sim.aStage[i] === A.NORMAL) { /* 画点 */ }
```

代价：远看时最多多几百个精灵。

## 5. 参数映射（我们 vs 原版）

| 参数 | 我们 | 原版 | 建议 |
|---|---|---|---|
| 感染时长 | `INCFG.quick = 8 s`（`sim.js:27`），零号病人 600~1800 s | 1/5/10/20/30/60/120/300 s，默认 **10** | 保留我们的 8 s（玩法上更"现代"），但把 10 s 也做成滑杆选项 |
| 咬合距离 | `BITE_R2 = 1.8 m`（`sim.js:49`） | 11 世界单位 ≈ 1.2 m | 保留 1.8（我们的人更小、帧率更低，1.2 会"永远咬不到"） |
| 咬死 | 变 `INFECTED` 且 hp=1（"咬死但还在走"） | 真死（倒地），尸变计时照走 | **保留我们的**（这是玩法差异，不是缺陷）；但**要补 `die01`**：咬死的人也应该先倒再爬 |
| 咬伤感染 | `infectChance=1`（咬到必感染） | 必感染 | 一致 |
| 丧尸倒地 | 无 | `zdie01` 1.65~3.75 s | 加上（顺带修 §1 的"啪一声变尸体"） |

> 也就是说：**"咬死→躺下→爬起"这三步我们其实一个都没有**，现在只有一个瞬时的 `state` 赋值。

## 6. 性能预算

| 项 | 现在 | 接入后 | 说明 |
|---|---|---|---|
| 图集显存 | 2048×19520×4 = **159.9 MB**（PNG 才 751 KB，全花在空 cell 上） | 2048×768×4 ≈ **6.4 MB** | 去变体 + 变量矩形，帧数还更多 |
| draw call | 2（精灵 + 圆点） | **3**（+阴影） | 阴影可整块关闭（低画质档） |
| 实例数 | 精灵 ≤ 20k，圆点 ≤ 20k | 阴影 ≤ 3k（只在近景开） | 阴影不需要给 2 万人画 |
| 内存数组 | — | 5 个数组 × 62k ≈ **0.85 MB** | 可忽略 |
| 每帧工作量 | `_pickAnim` 查表 | + 3 次数组读 + 1 次比较 | 可忽略 |
| 最坏情况 | 16× 快进 | 阶段动画会被"跳帧"（24 步/帧 → 1.2 s 仿真时间） | 和原版掉帧一个观感，可接受 |

## 7. 落地顺序与验收

| 步 | 做什么 | 验收（能看出对/错的东西） |
|---|---|---|
| **P0 数据** | 用 `reference/core` 重建图集（变量矩形、1 套实色 + 1 套白描边、`anim_ms`、`shadow` 条目） | `tools/audit_atlas_vs_original.py` 从 **39 支不符** 变 **0 支不符**；图集从 160 MB 降到 ~6 MB |
| **P1 状态** | `attach()` + `setInfected()` + 三个接线点 + `blocked` 冻结 | `node proposal/test_turnchain.mjs` 10/10；游戏里开 16× 快进，日志出现 `turn01 开始 → 播完 → ZOMBIE` |
| **P2 渲染** | `animFor` + 帧号 + 尸体分层 | 肉眼：中枪的人**有倒地过程**；被咬的人站着转身 7 s 才变 |
| **P3 阴影** | 阴影 pass | 放大截图对比 `shots/`：每人左下一团 (-8,-2) 的软黑影；屋内/尸体没有 |
| **P4 剪影** | 白描边 + 三色 tint | 屋里平民绿、警察蓝、丧尸红；尸变瞬间绿→红 |

P0 必须在 P1 之前 —— 否则 7.35 s 的 `turn01` 只有 37 帧（2.8 s），做出来的"慢"是假的。

## 8. 风险与回退

| 风险 | 说明 | 回退 |
|---|---|---|
| 视觉突变 | 现在"啪"地变尸体，接上后多了 3.75~6.84 s 的倒地 | 一个开关 `TURNCHAIN.enabled`，关掉就走老路径（`beginDie` 直接当 `NORMAL`） |
| 尸体复活破坏平衡 | 尸体变多 30% 的"活尸" | 只对"被咬过"的尸体（`riseAt>0`）生效，中枪但没被咬的尸体永远躺着 —— 这是我们对原版的**有意偏离**：原版里所有**人类尸体**都带 `Infectable`（状态 8 = `8|0x1000`），只有丧尸尸体（状态 14）不带 |
| 体型上移改了随机分布 | 现有个体体型在全城分布会变一次 | 只影响表现，不影响存档数值 |
| `far` 分支（`cdt=4×dt`）漏改 | 远处的人变 4 倍慢 | P1 的验收里专门看"远处的人变丧尸的时刻" |
| police01 缺 `zwalk` | **现在的 bug**：警察丧尸会 fallback 成 `police01/walk_solid`，像人一样走路 | P0 重建图集后 `_frames` 的兜底链可以删掉，改为"缺动画就报错" |
