修好确定性回归：家养/野生的抽签放到出生之后

现象：test_sim 的 determinism FAIL（同 seed 两次 reset 哈希不同），
     连跑三次 reset，家庭数 1067 → 1065 → 1064、动物数 54 → 59 → 62 每次都不一样。

根因：
  出生循环里就把 this.pet[i] 写成了 1（家养）。
  而出生循环末尾对每个个体都会调 pickWander()，它对家养动物用 homeX/homeZ 当中心
  ——可那时候家还没分配，读到的是**上一次 reset 残留的 homeX**。
  于是 walkable 判定结果不同 → 8 次重采样里消耗的 rng() 次数不同 →
  后面所有随机序列整体错位 → 动物数量、家庭数量全都不一致。

修法：
  出生时不写 pet；等 buildFamilies + 住址分配完成之后，
  再统一遍历一遍动物，用 h(i,92) 决定家养/野生，家养的才绑家。
  这样出生阶段的 pickWander 对所有个体都基于"当前位置"，随机数消耗稳定。

验证：
  determinism: 0fc32a236e94 vs 0fc32a236e94 -> PASS ✓
  连跑三次 reset：n=3089、家庭=1065、动物=60（家养 34）——三次完全一致 ✓
  test_chain 5/5。

这是典型的"用上次运行残留状态参与随机决策"的 bug，值得记一笔：
凡是 pickWander / 取随机点这类会读 homeX/homeZ 的地方，
都必须保证这些字段在出生阶段就是本局的初值。
