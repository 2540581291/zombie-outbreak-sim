寻路第 3 轮：粗网格排除室内 + 连通性泛洪过滤；并找到新的关键证据

改动：
1) buildCoarseGrid 里，室内格（nav.indoor 为真）不再计入可通行
   —— 移动层禁止室外的人进屋，寻路却把楼内当通路，两边规则打架，
      于是 A* 算出的路点落在楼里、人跟不进去 → 清路重算 → 无限循环。
2) 粗网格加连通性泛洪：从地图四边 BFS，走不到的格子一律封掉
   （四面围死的内院、没有门的楼内空间不再被当成通路）。

诊断工具：
· 新增 tools/trace_path.mjs —— 单个个体绕楼时逐帧打印
  pos / 剩余距离 / path 路点数 / pathIdx / 当前路点坐标 / 路点推进时刻

关键证据（真实地图，100×99m 的楼，起点到终点 124m）：
  路点序列是 (-363,623) → (-319,623) → (-295,623)，
  **这些点落在那栋楼的占地范围内**，而移动层进不去，
  所以每 3~4 秒就"算出路径 → 跟不动 → 清路径 → 重算"，
  40 秒只挪了 13m。

结论：病灶是 **寻路网格的"可走"定义与移动层的"能否进入"规则不一致**，
不只是跟随算法的问题。第 3 轮的室内排除/连通性过滤是对的方向，
但实测那栋楼的"内院"仍被判为连通（waypoints 依旧在楼里），说明
那片空间在 nav 里既不是 indoor、也确实与外部连通（有个窄口），
只是 move() 的探测扇形过不去。
